# 卡片视频交付说明（给外部写作模型）

> 你只负责产出 **`content.json` + `script.json`**。卡片渲染、配音、出片由接手方跑。
> 本文是"最短上手 + 必须遵守的硬约束"，字段全表见 `skills/article-rewrite/references/content-schema.md`。

## 0. 分工

| 环节 | 谁做 | 产物 |
|---|---|---|
| 写内容 | **你** | `content.json`（决定每张卡讲什么） |
| 写口播 | **你** | `script.json`（决定视频说什么） |
| 出卡片 | 接手方 | `cards.html`、`card-01.png…`、`overview.jpg` |
| 出视频 | 接手方 | `cards-video.mp4`（配音 + 字幕 + 卡内动画） |

```
原文 article.md
   └→ content.json ──→ 卡片（image-cards）──→ 卡片视频（card-video）─→ mp4
        └→ script.json ───────────────────────┘（配音 + 逐字对齐字幕）
```

**同一份 content.json 同时出图文和视频**，不要为视频另写一份。你也不写 `video.json` / 分镜。

## 1. 交付什么

1. `<工作目录>/content.json`
2. `<工作目录>/script.json`（口播稿，按卡分段）

外加回报：页数 / 节数（= 卡片张数）/ 总字数；用了哪些 role、预计几张卡；`script.json` 每卡的句数与预计时长；哪些数字或专名没把握。

不写：颜色、字体、尺寸、比例、平台名、张数、动画参数。

## 2. content.json 骨架

```jsonc
{
  "lang": "zh",
  "title": "两行大标题\n每行不超过十二个汉字",
  "series": "栏目名（可选）",
  "source": {
    "author": "原作者", "handle": "@handle",
    "title": "原文标题", "platform": "X 文章",
    "date": "2026-11-03", "url": "https://…"
  },
  "cover": {
    "title": "一个人\n就是一支\n**创意团队**",
    "kicker": "长文拆解 · 12 张图",
    "subtitle": "≤60 字，说清这组图/这条视频能给你什么",
    "points": ["第一条收获", "第二条收获", "第三条收获"],
    "cta": "收藏这组图，开始搭你的内容系统"
  },
  "xhs": {
    "title": "≤20 个字符",
    "caption": "第一句是钩子……300–600 字，末尾引导互动",
    "tags": ["大类", "具体主题", "人群", "作者名"]
  },
  "pages": [
    {
      "part": "第一部分 · 小标题",
      "intro": "2–3 句导语，≤120 字",
      "sections": [
        {
          "label": "节标签",
          "heading": "这一节讲什么\n可手动断行",
          "paragraphs": ["1–3 段，每段 ≤90 字"],
          "bullets": ["0–3 条，每条 ≤30 字"],
          "takeaway": "一句结论，≤26 字",
          "card": { "text": "卡面正文 ≤90 字", "bullets": ["≤3 条，每条 ≤26 字"], "figure": "none" },
          "figures": [ { "type": "bar", "caption": "图注 ≤24 字", "data": [["2024", 29.5, "$29.5B"]] } ]
        }
      ],
      "closing": "收束句 + 下页预告，≤60 字"
    }
  ]
}
```

必填：`lang`、`title`、`pages`（1–4 页，每页 3–4 节）。强烈建议：`source`、`cover`、`xhs`。

## 3. 每张卡 = 一个镜头

视频是一张一张卡推过去的，所以每一节都要能独立成卡、讲完一件事。

| 要求 | 说明 |
|---|---|
| 一节一件事 | 两个议题塞进一节，视频里就变成一段听不清的长独白 |
| 卡面 45–90 字 | 少于 45 字判"内容太薄"（头重脚轻的大留白）；多于 90 字装不下 |
| 口播 45–110 字 | 中文舒适语速约 4.5 字/秒，一卡约 10–25 秒；超 30 秒观众划走 |
| 卡面是摘要，口播是讲解 | 卡面字数受限，口播补"为什么"，但不要复述卡面 |
| 每节给 takeaway | ≤26 字，是结论不是复述；这一句成为视频的收束重音 |
| 相邻卡不同型 | 全篇一个版式读下来会睡着，灰模会直接拦 |

## 4. 每 1–2 张卡要有一个"会动的图"

视频里会自动长出来的只有五类原子：

| 原子 | 长什么样 | 来自哪些图 |
|---|---|---|
| `num` 数字滚动 | 数字从 0 滚到原值，小数位照写 | `stats`、`hbar` 的数值 |
| `bar` 横条 | 条宽从 0 拉到原值 | `hbar` |
| `col` 柱子 | 从基线长高，两根同时长 | `bar` |
| `draw` 连线 | 线一路描出（先立目标，再画线） | `tree`、`flow`、`converge`、`path` |
| `pop` 框与条目 | 框、对比栏、清单条目依次弹出 | `compare`、`panel`、bullets |

纯文字卡在视频里只有文字淡入，连续两张就闷。

| 内容 | 用 |
|---|---|
| 随时间变化的数字、几个数量对比 | `bar` |
| 两三个数量的比例 / 之前与之后 / 区间 | `hbar` |
| "有三种选择"，突出其中一个 | `stack` |
| 步骤、流程 | `flow` |
| 多个来源汇成一个结果 | `converge`（`"reverse": true` 表示一稿多发） |
| 层级结构 | `tree` |
| 一两个要记住的大数字 | `stats` |
| 简单算术关系 | `equation` |
| 成长路径 | `path` |
| 做 vs 不做、对 vs 错 | `compare` |
| 循环、飞轮、闭环 | `cycle` |
| 一句有力的原话 | `quote` |
| 原文配图 | `image` |
| 6–9 个并列概念、问题、分类 | `grid`（**图型**可用；别写成 `role: "grid"`） |

### 数字卡 `metric`（视频里最好用的一张）

一个数 + 一条走势，自己成一张卡。

```jsonc
{ "label": "验证", "heading": "两周跑完\n五十组样张",
  "metric": { "value": "50", "unit": "组", "label": "两周内出图总量",
              "values": [8, 19, 31, 42, 50], "labels": ["一", "二", "三", "四", "五"],
              "note": "同一套内容，换平台重渲" },
  "takeaway": "产量不是靠加班，是靠模板。" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `value` | 是 | 主数字，小数位照写（98.7 不会变 99） |
| `label` | 是 | 口径小字（≤14 字） |
| `unit` / `suffix` / `prefix` | 否 | 单位（另起小号）/ 紧跟符号（% ×）/ 前置符号（$ ¥）；`unit` 与 `suffix` 二选一 |
| `decimals` | 否 | 强制小数位 |
| `values` / `labels` | 否 | 走势（≥2 个数才画）与横轴标签，个数要对齐 |
| `note` | 否 | 数字说明（≤24 字） |
| `ring` + `total` | 否 | 表达"占整体的多少"，环只画比例、不做动画 |

- `metric` **优先于 role**（只有 checklist 在它前面），也优先于 `figures`：写了 metric 就不要再写这两个。
- **3:4 上数字卡中段会留 22–24% 空白**（版式偏松）。灰模描红时先补 `note` 或加 `values`（覆盖能到 74–85%），仍不过改用 `stat` 或 `bar`。

## 5. 封面：必须带一张图

- `cover.title` 2–3 行，每行 ≤10 字，用 `**关键词**` 标 1 处（变主色）。
- `cover.points` 3–5 条，每条 ≤16 字；`cover.subtitle` ≤60 字。
- **封面必须配一张图**：主题图标或一张贴题的配图，不做纯文字封面。
- 标题不要照搬原文标题，要更短、更有冲突感。

## 6. script.json：口播稿

```json
{
  "cards": [
    { "card": 1, "lines": ["开头这一句，先说清这条视频解决什么问题。"] },
    { "card": 2, "lines": ["第二张讲判断。", "一句一层，不要一口气念完三件事。"] },
    { "card": 3, "lines": ["第三张给数字。"] }
  ]
}
```

- `card` 对应卡片 `data-card`，**从 1 开始连续**；跳号等于少一镜。
- `lines` 按句分；字幕按 `，。！？、：；…` 自动切短语。
- **一句 12–25 字**：太长切成两行还跟不上，太短一句一闪。
- 口语，不念"本文将……"，不念符号和括号；数字写成口语（"百分之四十三"），产品名例外。
- 开场第一句给钩子或结论；结尾一句给行动（去看 / 收藏 / 试）。
- 视频张数不受图文 18/30 约束，按内容定；建议 10–14 张、3–5 分钟内。

## 7. 硬约束

字数按视觉宽度算：汉字/全角标点 = 1，字母/数字/半角 = 0.5。

| 对象 | 上限 |
|---|---|
| `title` | 2 行，每行 ≤12 汉字 |
| `heading` | ≤16 字；`role: opener` 时 ≤10 字 |
| `paragraph` | 每段 ≤90 字 |
| `bullets` | ≤30 字/条，≤3 条 |
| `takeaway` | ≤26 字 |
| `intro` | ≤120 字；`closing` ≤60 字 |
| `cover.title` | 2–3 行，每行 ≤10 字，1 处加粗 |
| `cover.subtitle` | ≤60 字；`points` 3–5 条 ≤16 字 |
| `card.text` | ≤90 字（图卡 ≤40 字） |
| `xhs.title` | ≤20 个字符 |
| `xhs.caption` | ≤1000 字，建议 300–600 |
| `xhs.tags` | 5–8 个，不写 # |

排版类：大标题里不写 `，` `。` `、`（引擎当断行并删掉符号）；中文断行必须自己写 `\n`；行内只支持 `**加粗**` 和 `\n`。

整组节奏：至少 3 种卡型；相邻两张不同型（同一节拆的续卡除外）；图卡 ≤40%；每 4 张内容卡至少 1 张轻卡（`claim` / `opener`）；内容卡 ≤12 张（3:4）；组卡建议 10–12 张。

role 写了就得给字段：

| role | 必给 |
|---|---|
| `claim` | `claim.text`（≤25 字）+ `claim.note`（≤40 字） |
| `compare` | `compare.left / right`，各含 title + items；每栏 2–4 条、每条 ≤14 字 |
| `timeline` | `timeline: [{at?, title, note}]`，3–6 个节点；`at` 只写真实时间 |
| `stat` | `stats: [{value, unit?, label, note?}]`，≤3 个 |
| `opener` | `heading` + 第一段导语 |
| `fig` | `figures` + `card.text`（说明 ≤40 字）+ 可选 `stats` |
| `metric` | `metric.value` + `metric.label`（见第 4 节） |

`role: "grid"` 已下线（写了直接报错）；`figures` 的图型 `grid` 仍然可用。

## 8. 画幅与平台

画幅由交付目标决定，出卡片时定死，视频跟着卡片走：

| 交付目标 | 出卡比例 | 视频尺寸 |
|---|---|---|
| 抖音竖版视频 / Stories | **9:16** | 1080×1920 |
| 小红书视频、公众号内嵌 | 3:4 | 1080×1440 |
| IG 轮播 | 4:5 | 1080×1350 |

- 抖音**图文**才是 3:4、≤30 张；**视频**要 9:16。小红书图文 3:4、≤18 张。微信 3:4、≤9 张。X 4:5、≤4 张。
- 换比例不用重写内容，但容量会变：1:1 最紧（正文 ≤50 字才好看）。

## 9. 脱敏（抖音/小红书默认必做）

标题、正文、标签、页脚、截图里不得出现厂商名、域名、主机名、产品内部代号；封面品牌图标换中性图标。目的地是抖音 / 小红书就必须脱敏，漏一个整组白做。站点原文与公众号不脱敏。

## 10. 内容口径

- 只用原文有的事实、数字、专名。原文没有的不补、不推测；拿不准在回报里标出。
- 不夸大：不写"月入十万""保姆级""全网最全""错过再等一年"。
- 每节只讲一件事；`takeaway` 是结论，不是复述正文。
- 图片里不放 emoji；`caption` 里可少量分段。
- 引用别人的观点标作者与标题，别写成自己的。
- 卡片是"手机一屏"，宁可少一条，不要塞满。
- 改稿只改被改动的节，其余逐字保持原样。

## 11. 交付前自检（必跑）

```bash
# 结构 + 字数
node skills/article-rewrite/scripts/check.mjs <工作目录>/content.json

# 版式方案 + 灰模：空卡、薄卡、卡型重复、超上限、覆盖率一次性点出来
node engine/scripts/render.mjs <工作目录>/content.json --platform 小红书 --plan
```

`--plan` 写 `plan.json` / `plan.png`，逐张列卡型、信息量、覆盖率与最大空带；灰模上描红的卡必须回改。

## 12. 常见被退稿的原因

1. 一节里塞两件事，卡面 120 字硬压。
2. 整组全是纯文字卡，视频里没有一处会动的东西。
3. 大标题里写了逗号，被引擎吃掉并乱断行。
4. 中文没写 `\n`，成图把词切开。
5. 卡面不到 30 字（45 字以下直接判 ✗）。
6. 口播一句 40 字，字幕切成三行还跟不上。
7. `script.json` 的 card 跳号，视频少一镜。
8. 抖音目的地没脱敏，出现厂商名或域名。
9. 写了 `role: "grid"`（图型 grid 不受影响）。
10. 封面纯文字没配图。
