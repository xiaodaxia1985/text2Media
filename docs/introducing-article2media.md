# article2media：给它一篇文章或一条视频，拿回一整套能发的图文和视频

> 一个开源的 Claude Code Skill：把文章或视频一键做成小红书图文、公众号排版和口播短视频。这篇讲它的能力、取舍，和一路踩过的坑。

作者：LeiLiu（GitHub：threerocks）· 发布于 2026-11-09 · 适用版本 1.6.0

一篇好文章写完，真正难的是让更多人读到它。

发到小红书要做成 3:4 卡片，发公众号要重新排版，发抖音、视频号要配音、做动画、加字幕。每个平台各做一遍，几个小时就过去了。结果往往是：要么只发一个平台，要么用截图草草了事。

**article2media 是一个开源的 Claude Code / Codex Skill，把一篇文章或一条视频做成能直接发布的中文视觉内容。**

- **输入**：
  - 文章：X 长文、网页、微信公众号文章、本地 Markdown；
  - 视频：抖音、YouTube、B 站链接，本地视频或音频，先转成逐字稿文章。
- **产出**：七种，包括杂志长图、小红书图文卡片、公众号排版、带 AI 配音和逐字字幕的口播短视频，以及原文排版、白板论证和漫画。
- **验收**：交付前，它会自己检查一遍，不合格就报错。
- **风格**：21 套主题，同一份内容可以随时换风格。
- **运行**：只需要 Node.js 22 和 Chrome，零 npm 依赖；本地配音和语音识别需要 Apple Silicon。
- **开源**：MIT 许可，仓库在 [github.com/threerocks/article2media](https://github.com/threerocks/article2media)。

这篇文章讲三件事：它能做什么，它和「让 AI 画张图」有什么不同，以及我们一路上做过的取舍。文中的数据基于 2026 年 11 月的 1.6.0 版。

## 一、article2media 能做什么：一份原文，七种产出

一条命令，七种产出：

![article2media 用同一篇 X 长文生成的七种产出：杂志长图、小红书卡片、公众号图文、口播视频、原文全文、白板论证、漫画，以及 21 套主题总览](https://raw.githubusercontent.com/threerocks/article2media/main/docs/showcase.jpg)

上图是同一篇 X 长文的全部产出。原文是 Dan Koe 的[《The most lucrative AI business to start in 2027》](https://x.com/thedankoe/status/2117664712532123680)，是英文的，产出全部是中文。[示例视频](https://github.com/threerocks/article2media/blob/main/docs/samples/dan-koe-video.mp4)和 [6 款音色的试听](https://github.com/threerocks/article2media/tree/main/docs/samples/voices)都在仓库里。

为了展示不同风格，示例里每种产出各用了一套主题：
- **长图**：商业杂志 editorial；
- **小红书卡片**：新粗野 brutal；
- **公众号**：瑞士极简 swiss；
- **口播视频**：深色科技 midnight，配音用「资讯播报男声」。

七种产出的规格和用途如下：

| 产出 | 规格和内容 | 适合 |
|---|---|---|
| **杂志长图** | 每节有标题、要点、两张图表和一个数据面板，结尾附执行清单 | 把长文读成一份可收藏的拆解 |
| **卡片组** | 小红书 3:4，以及 4:5、1:1、9:16，附发帖文案 | 信息流平台 |
| **公众号图文** | 复制后直接粘贴进编辑器，附头图和封面 | 公众号 |
| **口播视频** | 1080×1920 竖屏，本地配音，动画和字幕随口播逐字出现 | 短视频平台 |
| **原文全文** | 一字不改，只做排版 | 想完整保留原文 |
| **白板论证** | 把作者的推理过程摊成一条主干 | 看清作者怎么得出结论 |
| **漫画** | 黑白分镜讲清一个机制，角色前后一致 | 用故事讲道理 |

用法很简单，在 Claude Code 里说一句话就行：

```
/article2media https://x.com/xxx/status/xxx            # 默认出长图
/article2media https://x.com/xxx/status/xxx 小红书      # 卡片组
/article2media ./notes.md 公众号                        # 公众号排版
/article2media https://example.com/post 做成口播视频     # 竖屏视频
```

可以输入 X 长文、帖子和线程，普通网页，微信公众号文章，本地 Markdown，也可以直接粘贴正文。

原文也可以是一条视频。给它抖音、B 站、YouTube 的链接，或者一段本地视频、录音，它会先转成逐字稿文章，后面的流程完全一样：

```
/article2media https://www.bilibili.com/video/BV1NprhBPEtR 小红书     # 视频进，图文出
/article2media ./访谈录音.m4a 公众号
```

风格有 21 套：商业杂志、瑞士极简、深色科技、液态玻璃、多巴胺、新粗野、国潮、新中式、像素、电影感……不指定时，Claude 会按内容和投放平台挑一个，并告诉你为什么选它。

## 二、它和「让 AI 画张图」有什么不同

先看一张对比，下面六点逐条展开：

| | 常见做法 | article2media |
|---|---|---|
| 内容 | 截图，或把全文压成一段摘要 | 先读懂，再按结构重组、配图表 |
| 图里的中文 | 让 AI 直接画进图里，常写错字 | 图里不放字，所有文字用 HTML 排版 |
| 质量把关 | 发布前靠人眼检查 | 每种产出都有自动验收，不合格就报错 |
| 视频 | 图片轮播加机器朗读 | 逐字同步的动画、48 kHz 配音、审片报告 |
| 原文 | 只收文章 | 文章或视频，视频先转成逐字稿 |
| 运行 | 依赖云端服务 | 本地优先，零 npm 依赖，缺什么就降级 |

### 1. 先读懂，再排版

article2media 不截图，也不是把全文压成一段摘要。

Claude 的工作是理解和写作：规划结构，改写标题，决定哪一节配柱状图、哪一节配流程图，必要时联网核对文中的数字。它产出的是一份只有内容、没有任何样式的 `content.json`。

排版、截图、配音、对齐这些确定性的工作，全部交给脚本。

这样分工带来两个好处：

- **换风格不用重写。** 同一份内容可以渲染成 21 套主题中的任何一套，也可以同时出长图、卡片和公众号。
- **结果可复现。** 同样的输入得到同样的输出，方便检查，也方便修。

### 2. 图里不放一个字

AI 画图最大的问题之一，是中文字会画错。

article2media 的做法是：生成的图片里不放任何文字。所有文字，包括标题、图表标签、漫画对白、视频字幕，都用 HTML 排版，再由无头 Chrome 截图。

这意味着字永远不会乱码，随时能改；更重要的是，程序能把渲染出来的文字读回来检查。

### 3. 每种产出都要过验收

AI 生成的东西最怕「看起来差不多」。所以每一种产出都有自己的验收，不合格就直接报错退出，而不是交给人用眼睛去找：

- **长图、卡片、公众号**：检查文字溢出、截断、元素重叠、单字成行、图片和字体加载失败。
- **原文全文**：每个段落都登记进账本，渲染后在浏览器里逐块读回比对。改一个字、调一次顺序、漏一段，都会失败。
- **白板论证**：原文的每一段都必须有去向，要么进入推理的某一步，要么写明为什么省略。
- **口播视频**，每次成片都出一份审片报告：
  - 首句是否在 5 秒内说完；
  - 第一个画面信息是否在 2.5 秒内出现；
  - 画面最长静止了多久；
  - 旁白语速；
  - 字幕有没有闪断；
  - 每一句配音的错字率和音色漂移；
  - 成片响度。

下面是示例视频（Dan Koe 那篇，midnight 主题、资讯播报男声）的真实审片输出：

```
审片：video/midnight/contact-sheet.jpg
  ✓ 首句说完：4.83s
  ✓ 第一个画面信息：0.75s
  ✓ 最长画面静止：4.7s
  ✓ 字幕停留过短（<0.55s）：0 条
  ✓ 旁白语速：4.37 字/秒（约 262 字/分钟，宜 ≤ 5.2）
  ✓ 字幕闪断（<0.6s 的空档）：0 处
  ✓ 字幕平均停留：2.07s（33 条，pill）
  ✓ 配音质检：18 段，0 段有问题
  ✓ 成片响度：-16.2 → -14 LUFS（48 kHz）
```

自测矩阵覆盖 4 篇示例文章 × 6 种版式 × 21 套主题，共 504 次渲染，每次都要求 0 个版面错误。

### 4. 视频不是「幻灯片加朗读」

很多图文转视频工具，做法是把图片轮播一遍，再配一段机器朗读。

article2media 的视频是按短视频的规律设计的：

- **开场**：第一帧是封面，然后是一句 5 秒内说完的钩子。
- **逐字同步**：本地 Whisper 给出每个字的时间戳，数字滚动、清单打勾、关键词高亮，都在口播说到那个字的瞬间出现。
- **镜头**：10 种镜头类型，每镜最后一个元素出现后至少留 1.1 秒，让观众看清。
- **配音**：本地 VoxCPM2 生成 48 kHz 配音，逐句检查错字、截断、削波、音色漂移和英文漏读，不合格就自动重做。
- **节奏**：语速按「从容讲解」控制在每秒 4.5 字左右。
- **字幕**：单行显示，不闪烁，样式跟着主题走。

### 5. 版权和合规，从第一天就写进流程

- **随包音色**：6 款音色全部只凭文字描述设计，不模仿任何真人。
- **克隆音色**：只能进本机个人音色库，不随项目分发，用于成片时会提醒确认授权。
- **AI 标识**：成片首帧和 MP4 元数据都带 AI 生成标识，发布文案里附 AI 生成声明。
- **出处**：每张图都署原文出处。

### 6. 零依赖，本地优先

article2media 只需要 Node 22 和一个 Chrome，没有任何 npm 依赖。

出图、本地配音、逐字对齐、视频转写都是可选能力：

- **出图**：优先用 Codex CLI，ChatGPT 登录就能用，不需要 API key。
- **配音**：依次是本地 VoxCPM2、免费的 edge-tts、系统语音。
- **对齐**：有 Whisper 就逐字对齐，没有就退回估算。
- **视频转写**：有字幕用字幕；没有字幕时，有本地 Whisper 就识别，没有就请你提供字幕文件。

缺了哪项，它就降级或者明确告诉你缺什么。它从不自动下载或安装任何东西。

## 三、从 1.0 到 1.6：一路上的取舍

article2media 从第一版到现在的 1.6.0，前后三天、八个版本。下面这些转折，每一个都改变了它的样子。

### 起点：只想把一篇 X 长文读成一张中文长图

第一版只做长图和卡片。很快我们就确定了一个原则：**让模型做判断，让脚本做测量。**

模型擅长理解和写作，但它不知道一行字会不会溢出边框。所以排版之后必须有一道版面检查，而且这道检查不能靠模型「觉得没问题」。

### 一个「回」字

做新中式主题时，我们选了一款很好看的标题字体。版面检查全部通过，可人一看成品，所有的「回」字都是一个实心黑块。

字体文件本身就是坏的，程序检测不出来。从那以后，每款新字体都要用「回图国圆品器噩」这几个字先试一遍。

这件事让我们明白：机器检查必须有，人眼也省不掉。现在每次改版式，除了跑自测，还要真的去看渲染出来的图。

### 公众号编辑器会吃掉你的样式

公众号编辑器会丢掉 class、外部 CSS 和网络字体，粘贴进去的东西往往面目全非。

我们的解法是：从主题把每个元素的最终样式算出来，全部写成内联样式；图表截成 3 倍图，用 base64 嵌进正文，不需要图床。复制，粘贴，就是成品。

### 主题不是按题材选的

有一次处理一篇讲普通人做自媒体涨粉的文章。按「个人经历」这个题材，指南选了沉稳的大地色。成品出来，判断很直接：这个主题不好。

这类内容的读者在小红书和 X 上，要的是明亮、年轻、抓眼的风格，最后换成了多巴胺。

从此，选主题的顺序变成「明确偏好 → 题材 → 投放场景」，场景和受众的分量不比题材轻。

### 从图到视频

最早的视频实验很简单：把卡片轮播一遍，配上朗读和背景音乐。能看，但不像一条短视频。

正式版重做了整条链路：Claude 先当导演写分镜，脚本负责配音、逐字对齐、动画、混音和审片。黄金 5 秒钩子、每个数字在说到时才出现，这些都是那时候定下来的。

### 做减法：背景音乐

背景音乐我们试了三次：

1. 在线免版权曲库；
2. 程序合成的和弦铺底；
3. 本地 AI 作曲，光模型就 11 GB。

最后一个都没留。

原因很简单：太重了，而且平台 App 里加背景音乐只要几秒钟。这一版的视频只有配音和很轻的转场音。

一个功能能做，不代表应该做。

### 声音的版权：克隆后再合成，还是原来那个人

做配音时，最自然的想法是克隆几个大家耳熟能详的「国民音色」。我们认真问过自己一个问题：用 AI 把克隆来的声音再合成一遍，算不算一个新声音？

结论是不算。只要听众还能认出是谁，声音权益就仍然属于原来那个人。

- **法条**：《民法典》第 1023 条第二款写明：「对自然人声音的保护，参照适用肖像权保护的有关规定。」
- **判例**：2024 年 4 月，北京互联网法院审结了一起 AI 生成声音人格权侵权案，认定只要一般听众能从 AI 合成的声音里认出是谁，这个声音就同样受保护。

所以音色库按版权分成了两层：

- **公开音色**：随项目分发的 6 款，全部只凭文字描述生成。我们先归纳受欢迎音色的风格特征，再用文字重新设计，生成多个候选，最后由人耳挑选。
- **本机个人音色库**：克隆来的声音只能放在这里，只供本人制作。

默认永远使用公开音色。

### 「解说太急，是大忌」

1.4 版的音色做好后，第一轮试听的反馈很直接：有两款声音太急了。「做解说整体语速都不能太急，这个是大忌。」

我们去测了一下。默认的那款解说男声，参考音频每秒 6.6 个字，成片也有每秒 6 个字，确实像在赶路。

追下去发现：VoxCPM2 会照着参考音频的节奏读。在声音描述里写「语速偏慢」，它完全不理会。最后的办法是用可控克隆，保留原音色，只把参考音频本身放慢，有一款要连做两轮才降下来。

但真正的改变，是把一句「太急了」变成了数字：

- **语速标准**：试听里被评价「很好」的那一版，平均每秒 4.7 个字。据此定下标准约 4.5 字/秒，单段超过 5.2 字/秒判为偏快。
- **自动处理**：偏快的句子换种子重新生成；还快，就在保持音高的前提下放慢，最多 15%。
- **首句长度**：首句压到 19 个字以内，说不完就删字，不靠加快语速。

调整后，同一条视频的旁白从每秒 5.97 字降到 4.27 字。

### 字幕为什么一直在闪

同一轮反馈的另一半：「字幕一直闪烁。」

拆开看，「闪」有四个来源：

1. 每换一条字幕都有一次缩放弹跳；
2. 字幕底板随字数变宽变窄；
3. 句间的短暂停顿里，字幕会消失再出现；
4. 平均 1.2 秒就换一条，眼睛根本跟不上。

修法是逐条对应的：

1. 换字幕改为硬切；
2. 字幕单行显示，太宽就缩小字号；
3. 1.4 秒以内的停顿里，字幕一直保留；
4. 同一句话里的短语合并成一行，每行不超过 13 字。

字幕条数从 39 条减到 29 条，平均停留从 1.2 秒拉长到 2.2 秒以上，闪断 0 处。

顺手，我们给 21 套主题各配了一套字幕样式：多巴胺用白字粗描边，国潮用朱红印章做关键词，电影感用宽银幕字幕。

![article2media 口播视频的 21 套字幕样式：卡片、描边贴纸、硬框、无框墨字、荧光笔、电影字幕、毛玻璃](https://raw.githubusercontent.com/threerocks/article2media/main/docs/caption-styles.jpg)

这些标准，包括语速、首句时长和字幕闪断，现在都写进了审片。下次谁再改代码，机器会替我们记住那句「太急了」。

### 从 article2img 到 article2media

项目最早叫 article2img，因为第一版只出图。后来有了公众号排版和口播视频，这个名字就说小了：搜「文章转视频」的人找不到它，AI 回答相关问题时也想不到它。

1.5.0 改名为 article2media。挑名字时我们看了三点：

- 在 GitHub 和 npm 上没有重名，搜名字就能直接找到它；
- 名字本身说明用途，没见过它的人和 AI 也能猜对；
- 和旧名一脉相承，以前的提及仍能对上号。

换示例文章时还有个小插曲。新示例是一篇英文 X 长文，原文全文排版直接报了错：解析出的文字和原文差了一个星号。

原因是原文里斜体紧挨着粗斜体（`***…***`），解析器漏了这种写法。原文块账本把它拦了下来，没有让一张「看起来没问题」的图交出去。修好之后，这个用例也进了自测。

### 视频也能当原文

很多好内容不在文章里，在视频里：一期深度解读、一场访谈、一段课程。以前要先找个工具把视频转成文字，再交给 article2media。1.6.0 把这一步并了进来，给链接或文件就行。

文字从哪来，按可信程度排：

1. 人工字幕；
2. 平台按原语言生成的自动字幕；
3. 本地 Whisper 识别。

有两类东西看着像字幕，其实不能用：

- **机器翻译的字幕轨**：不是说话人的原话；
- **B 站弹幕**：在 yt-dlp 里也算一条「字幕」，其实是观众评论。

所以这两类都不用。

转出来的逐字稿也守同一条规矩：**只补标点，不改字**。Whisper 用空格表示停顿，我们把它换成逗号，段尾补句号。人名、术语识别错了，就用提示词和词表来纠正，不去猜。实测在 Apple Silicon 上，14 分钟的视频 29 秒转完。

做这一版时还遇到一件事。抖音的分享页最近不再直接带视频数据，原来的解析方法拿不到东西。我们没有去研究平台的私有接口来绕过它，而是交给用户选：

- 你同意复用本机浏览器的状态，就加一个参数，交给 yt-dlp 去取；
- 或者在 App 里把视频保存到本地，直接交文件。

本地文件这条路，用一条 14 分钟的抖音视频完整跑通了。支持哪些来源、文字怎么清理、产出放在哪，见[视频输入说明](https://github.com/threerocks/article2media/blob/main/skills/video-transcript/references/video-input.md)。

## 四、几条心得

**模型做判断，脚本做测量。** 读懂、取舍、改写交给模型；能量化的，比如溢出、时长、语速、闪断，全部交给程序检查。两者各守一边，质量才稳。

**把「感觉不对」翻译成指标。** 「太急」「太闪」「这个主题不好」，都是很有价值的反馈。但只有变成 4.5 字/秒、0 处闪断、按场景选主题这样的规则，它才不会在下一个版本里复发。

**能力可选，体验降级而不是失败。** 没有 GPU 就用在线语音，没有出图能力就用纯排版。每多一个硬依赖，就少一批能用上它的人。

**合规前置。** 版权和 AI 标识这些事，事后补的成本远高于一开始就做对。

## 五、现在的边界：哪些还做不到

- **本地配音**：VoxCPM2 目前只在 Apple Silicon 上运行，其他机器用 edge-tts 或系统语音。
- **出图**：AI 插画和漫画需要出图能力，比如 Codex CLI 登录，或者 OpenAI、Gemini 的付费 key。
- **背景音乐**：视频暂时没有背景音乐。
- **X 抓取**：X 内容依赖 FxTwitter，它不可用时需要手动粘贴正文。
- **视频输入**：本地语音识别需要 Apple Silicon；YouTube 在有的网络下要求登录确认，抖音有时也要求浏览器 cookie，这时需要你同意复用浏览器状态，或者把视频保存到本地再交给它。
- **听感**：音色和语速的最终判断仍然要靠人耳。

## 六、常见问题（FAQ）

### article2media 是什么？

article2media 是一个开源的 Claude Code / Codex Skill，也是 Claude Code 插件。它把一篇文章或一条视频做成能直接发布的中文视觉内容：
- 杂志长图；
- 小红书图文卡片；
- 公众号排版；
- 口播短视频；
- 原文排版、白板论证和漫画。

原文也可以是视频：抖音、YouTube、B 站链接，或者本地视频和录音，会先转成逐字稿文章。它在 1.5.0 之前叫 article2img。

### 能把抖音、B 站、YouTube 视频做成小红书图文吗？

能。直接给链接，比如 `/article2media https://www.bilibili.com/video/BV… 小红书`，抖音整段分享口令也可以。

1. 视频先转成逐字稿文章：有字幕用字幕，没有就用本地 Whisper 识别。
2. 之后和文章一样，改写成卡片、长图、公众号或口播视频，来源署原视频的作者。

### 怎么把一篇文章做成小红书图文？

安装后在 Claude Code 里输入 `/article2media <链接> 小红书`，它会做三件事：
1. 抓取原文；
2. 改写成 3:4 卡片组：封面、每节一张卡、要点总结；
3. 附一份可直接复制的发帖文案。

链接可以是 X 长文、普通网页或公众号文章，也可以给本地 Markdown 文件。

### 能把文章自动做成口播视频吗？

能。说「做成口播视频」，Claude 会先写分镜脚本，再由脚本完成配音、逐字对齐、动画、字幕、封面和审片，产出 1080×1920 的竖屏视频。

- **配音**：Apple Silicon 上用本地 VoxCPM2，其他机器用免费的 edge-tts 或系统语音。
- **音色**：随包 6 款。

### 需要付费 API 或 GPU 吗？

图文产出不需要，只要 Node.js 22 和 Chrome。AI 插画和漫画需要出图能力：Codex CLI 用 ChatGPT 账号登录即可，或者使用 OpenAI、Gemini 的付费 key。

### 配音可以商用吗？

- **随包音色**：6 款都由 VoxCPM2 只凭文字描述生成，不模仿任何真人。
- **克隆音色**：只能放在本机个人音色库，不随项目分发；使用时会提醒你确认授权。
- **AI 标识**：成片带 AI 生成标识。

### 支持英文文章吗？

支持。英文原文默认改写成中文产出，本文的示例就是一篇英文 X 长文。需要英文产出时加 `--lang en`。
