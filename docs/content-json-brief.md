# 内容与口播稿交付说明（给外部写作模型）

> 你只负责产出 **`content.json` + `script.json`**。卡片渲染、配音、出片、发布由接手方跑。
> 仓库里已有官方 schema，本文是"最短上手 + 必须遵守的硬约束"，不重复它。

## 0. 先读这几份（按顺序，别跳）

| 文件 | 讲什么 |
|---|---|
| `skills/article-rewrite/references/content-schema.md` | 顶层 / Page / Section / role / `metric` 的全部字段与字数上限 |
| `skills/article-rewrite/references/figures.md` | 图表类型（bar / hbar / stack / flow / grid / converge / tree / stats / equation / path / compare / cycle / quote / svg / image）与各自字段 |
| `skills/image-cards/references/xhs-guide.md` | 卡片专用三件套：`cover` / `card` / `xhs` 怎么写 |
| `skills/card-video/SKILL.md` | 视频怎么从卡片长出来（哪些图元素会动、字幕怎么切） |

写完必须跑第 13 节的自检，不跑等于没交。

## 1. 交付什么

- 两个文件：`<工作目录>/content.json`、`<工作目录>/script.json`（口播稿）。
- **一篇文只交一份 content.json**，小红书、抖音、公众号都从这一份渲；视频也从这一份出，不要为视频另写一份。
- 文件里**只放内容**：不要写颜色、字体、宽高、比例、平台名、张数——那些由渲染参数决定。
- 允许写 `theme`（主题名，或 `{"long":"…","cards":"…","wechat":"…"}` 分开指定）；不写也行，渲染端会按 `styles.md` 选。
- 不要写 `video.json` / 分镜，那是另一套东西。不要动仓库里任何其它文件。

```
原文 article.md
   └→ content.json ──→ 卡片（image-cards）──→ 卡片视频（card-video）─→ mp4
        └→ script.json ───────────────────────┘（配音 + 逐字对齐字幕）
```

## 2. content.json 最小骨架（这个结构能直接跑通）

```jsonc
{
  "lang": "zh",
  "title": "两行大标题\n每行不超过十二个汉字",
  "series": "栏目名（可选）",
  "source": {
    "author": "原作者", "handle": "@handle",
    "title": "原文标题", "platform": "X 文章",
    "date": "2026-11-03", "url": "https://…"
  },
  "cover": {
    "title": "一个人\n就是一支\n**创意团队**",
    "kicker": "长文拆解 · 15 张图",
    "subtitle": "说清这组图能给你什么，≤60 字",
    "points": ["第一条收获", "第二条收获", "第三条收获"],
    "cta": "收藏这组图，开始搭你的内容系统"
  },
  "xhs": {
    "title": "≤20 个字符的标题",
    "caption": "第一句是钩子……300–600 字，末尾引导互动",
    "tags": ["大类", "具体主题", "人群", "作者名"]
  },
  "pages": [
    {
      "part": "第一部分 · 小标题",
      "intro": "2–3 句导语，≤120 字",
      "sections": [
        {
          "label": "节标签",
          "heading": "这一节讲什么\n可手动断行",
          "paragraphs": ["1–3 段，每段 ≤90 字"],
          "bullets": ["0–3 条，每条 ≤30 字"],
          "takeaway": "一句结论，≤26 字",
          "card": { "text": "卡片正文 ≤90 字", "bullets": ["≤3 条，每条 ≤26 字"], "figure": "none" },
          "figures": [ { "type": "bar", "caption": "图注", "data": [["2024", 29.5, "$29.5B"]] } ]
        }
      ],
      "closing": "收束句 + 下页预告，≤60 字"
    }
  ]
}
```

必填：`lang`、`title`、`pages`（1–4 页，每页 3–4 节）。
强烈建议：`source`（页脚来源行）、`cover`（没有就退化用 title + intro，封面会很难看）、`xhs`（没有就没有发帖文案）。

## 3. script.json 骨架

```json
{
  "cards": [
    { "card": 1, "lines": ["开头这一句，先说清这条视频解决什么问题。"] },
    { "card": 2, "lines": ["第二张讲判断。", "一句一层，不要一口气念完三件事。"] },
    { "card": 3, "lines": ["第三张给数字。"] }
  ]
}
```

- `card` 对应卡片 `data-card`，**从 1 开始连续**；跳号等于视频少一镜。
- `lines` 按句分；字幕按 `，。！？、：；…` 自动切短语。
- 视频张数不受图文 18/30 的约束，按内容定；建议 10–14 张、3–5 分钟内。

## 4. 每张卡 = 一个镜头

视频是一张一张卡推过去的，所以每一节都要能独立成卡、讲完一件事。

| 要求 | 说明 |
|---|---|
| 一节一件事 | 两个议题塞进一节，视频里就变成一段听不清的长独白 |
| 卡面 45–90 字 | 少于 45 字判"内容太薄"（头重脚轻的大留白）；多于 90 字装不下 |
| 口播一卡 45–110 字 | 中文舒适语速约 4.5 字/秒，一卡约 10–25 秒；超 30 秒观众划走 |
| 卡面是摘要，口播是讲解 | 卡面字数受限，口播补"为什么"，但不要复述卡面 |
| 每节给 `takeaway` | ≤26 字，是结论不是复述；这一句成为视频的收束重音 |

## 5. 每 1–2 张卡要有一个"会动的图"

视频里会自动长出来的只有五类原子：

| 原子 | 长什么样 | 来自哪些图 |
|---|---|---|
| `num` 数字滚动 | 数字从 0 滚到原值，小数位照写 | `stats`、`hbar` 的数值、`metric` |
| `bar` 横条 | 条宽从 0 拉到原值 | `hbar` |
| `col` 柱子 | 从基线长高，两根同时长 | `bar` |
| `draw` 连线 | 线一路描出（先立目标，再画线） | `tree`、`flow`、`converge`、`path` |
| `pop` 框与条目 | 框、对比栏、清单条目依次弹出 | `compare`、`panel`、bullets |

纯文字卡在视频里只有文字淡入，连续两张就闷。按内容挑图型：

| 内容 | 用 |
|---|---|
| 随时间变化的数字、几个数量对比 | `bar` |
| 两三个数量的比例 / 之前与之后 / 区间 | `hbar` |
| "有三种选择"，突出其中一个 | `stack` |
| 步骤、流程 | `flow` |
| 多个来源汇成一个结果 | `converge`（`"reverse": true` 表示一稿多发） |
| 层级结构 | `tree` |
| 一两个要记住的大数字 | `stats` |
| 简单算术关系 | `equation` |
| 成长路径 | `path` |
| 做 vs 不做、对 vs 错 | `compare` |
| 循环、飞轮、闭环 | `cycle` |
| 一句有力的原话 | `quote` |
| 原文配图 | `image` |
| 6–9 个并列概念、问题、分类 | `grid`（**图型**可用；别写成 `role: "grid"`） |

## 6. 数字卡 `metric`（视频里最好用的一张）

一个数 + 一条走势，自己成一张卡。

```jsonc
{ "label": "验证", "heading": "两周跑完\n五十组样张",
  "metric": { "value": "50", "unit": "组", "label": "两周内出图总量",
              "values": [8, 19, 31, 42, 50], "labels": ["一", "二", "三", "四", "五"],
              "note": "同一套内容，换平台重渲" },
  "takeaway": "产量不是靠加班，是靠模板。" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `value` | 是 | 主数字，小数位照写（98.7 不会变 99） |
| `label` | 是 | 口径小字（≤14 字） |
| `unit` / `suffix` / `prefix` | 否 | 单位（另起小号）/ 紧跟符号（% ×）/ 前置符号（$ ¥）；`unit` 与 `suffix` 二选一 |
| `decimals` | 否 | 强制小数位 |
| `values` / `labels` | 否 | 走势（≥2 个数才画）与横轴标签，个数要对齐 |
| `note` | 否 | 数字说明（≤24 字） |
| `ring` + `total` | 否 | 表达"占整体的多少"，环只画比例、不做动画 |

- `metric` **优先于 role**（只有 `kind: "checklist"` 在它前面），也优先于 `figures`：写了 metric 就不要再写这两个。
- 校验会拦：缺 `value`、`values` 有非数字、`labels` 与 `values` 个数不符。
- **3:4 上数字卡中段会留 22–24% 空白**（版式偏松）。灰模描红时先补 `note` 或加 `values`（覆盖能到 74–85%），仍不过改用 `stat` 或 `bar`。

## 7. 封面：必须带一张图

- `title` 2–3 行，每行 ≤10 字，用 `**关键词**` 标 1 处（变主色）。
- `points` 3–5 条，每条 ≤16 字；`subtitle` ≤60 字。
- **封面必须配一张图**：主题图标或一张贴题的配图，不做纯文字封面。
- 标题不要照搬原文标题，要更短、更有冲突感。不要夸大。

## 8. 硬约束（违反会被 `--plan` / `--check` 拦下来）

**字数按视觉宽度算**：一个汉字或全角标点 = 1，一个字母/数字/半角符号 = 0.5。

| 对象 | 上限 |
|---|---|
| `title` | 2 行，每行 ≤12 汉字 |
| `heading` | ≤16 字；`role: opener` 时 ≤10 字 |
| `paragraph` | 每段 ≤90 字 |
| `bullets` | ≤30 字/条，≤3 条 |
| `takeaway` | ≤26 字 |
| `intro` | ≤120 字；`closing` ≤60 字 |
| `cover.title` | 2–3 行，每行 ≤10 字，1 处 `**关键词**` |
| `cover.subtitle` | ≤60 字；`cover.points` 3–5 条，≤16 字 |
| `card.text` | ≤90 字（`role: fig` 时 ≤40 字） |
| `xhs.title` | ≤20 个字符（字母空格都算 1） |
| `xhs.caption` | ≤1000 字，建议 300–600 |
| `xhs.tags` | 5–8 个，不写 `#` |

**排版类**

- 大标题里**不要写** `，` `。` `、`——引擎会当断行用并把符号删掉。要断行就自己写 `\n`。
- 中文断行必须自己写 `\n`：引擎按字宽断，会把词切开（"产 / 品"）。
- 行内只支持 `**加粗**` 和 `\n`；其它 Markdown、HTML 会按原文转义显示。

**卡片节奏（`--plan` 会逐条查）**

- 整组至少 3 种卡型；相邻两张不能同型（同一节拆的续卡除外）；
- 图卡 ≤40%；每 4 张内容卡至少 1 张"轻卡"（`claim` / `opener`）；
- 内容卡 ≤12 张（3:4）；非主张/章节页的卡少于 **45 字** 会报 ✗（内容太薄）；
- 单卡容量：主张 ≤25 字、对比每栏 2–4 条 ≤14 字、时间线 3–6 节点、数字 ≤3 个。

**role 写了就要给对应字段**，否则退化成常规卡并在灰模上点名：

| role | 必给字段 |
|---|---|
| `claim` | `claim.text`（≤25 字）、`claim.note`（≤40 字） |
| `compare` | `compare.left` / `compare.right`，各含 `title` + `items` |
| `timeline` | `timeline: [{at?, title, note}]`，`at` 只写真实时间，不写 01/02 |
| `stat` | `stats: [{value, unit?, label, note?}]`，≤3 个 |
| `opener` | `heading` + 第一段（导语） |
| `fig` | `figures` + `card.text`，可选 `stats` |

**界格 `role: "grid"` 已于 2026-11-11 下线**，写了会直接报错。并列的短词改写成 `claim`，或并进相邻卡。注意：`figures` 里的**图型 `grid`** 仍然可用，两者不是一回事。

## 9. 画幅与平台

画幅由交付目标决定，出卡片时定死，视频跟着卡片走：

| 交付目标 | 出卡比例 | 视频尺寸 | 张数上限 |
|---|---|---|---|
| 抖音竖版视频 / Stories | **9:16** | 1080×1920 | 按内容，不受图文上限约束 |
| 小红书视频、公众号内嵌 | 3:4 | 1080×1440 | — |
| IG 轮播 | 4:5 | 1080×1350 | 20 |

**图文**张数上限（以 `engine/scripts/lib/platforms.mjs` 为准）：

| 平台 | 比例 | 单篇上限 |
|---|---|---|
| 小红书 | 3:4（1080×1440） | 18 |
| 抖音 | 3:4（1080×1440） | **30** |
| 微信 | 3:4 | 9 |
| X | 4:5 | 4 |

> `skills/image-cards/SKILL.md` 的表格里还写着抖音 12，那是改版前的旧值，已被 `platforms.mjs` 覆盖；以代码为准。9:16 不是小红书/抖音图文的规格，套进 3:4 画框会左右各裁约 12.5%。

## 10. 脱敏（抖音/小红书默认必做）

标题、正文、标签、页脚、截图里不得出现厂商名、域名、主机名、产品内部代号；封面品牌图标换中性图标。目的地是抖音 / 小红书就必须脱敏，漏一个整组白做。站点原文与公众号不脱敏。

## 11. 内容口径（工具查不出来，但你得守）

- 只用原文有的事实、数字、专名。原文没有的不补、不推测；拿不准就标出来。
- 不夸大：不写"月入十万""保姆级""全网最全""错过再等一年"。
- 每节只讲一件事；`takeaway` 是结论，不是把正文再复述一遍。
- 图片里不放 emoji；`caption` 里可少量分段。
- 引用别人的观点要标作者与标题，别写成自己的。
- 卡片是"手机一屏"，宁可少一条，不要塞满。
- 口播口语化：不念"本文将……"，不念符号和括号；数字写成念出来的样子（"百分之四十三"），产品名例外。

## 12. 改稿时（增量，不是重写）

- 只改被改动的节，其余节**逐字保持原样**——整组重渲后前后不一致，比错字更糟。
- 字段有增删时同步检查 `cover.points` 和末张 takeaway 列表是否还对得上。
- `script.json` 跟着改：卡数变了要重编 `card` 序号，别留空号。
- 改完照样跑第 13 节自检。

## 13. 自检（交付前必跑，不出图）

```bash
# 只校验结构，快
node skills/article-rewrite/scripts/check.mjs <工作目录>/content.json

# 出版式方案 + 灰模：把空卡、薄卡、卡型重复、超上限、内容覆盖不足全部点出来
node engine/scripts/render.mjs <工作目录>/content.json --platform 小红书 --plan
```

`--plan` 会写 `plan.json` / `plan.png`，逐张列卡型、信息量、覆盖率与最大空带；灰模上描红的卡必须回改。

## 14. 交付时回报这几项

- 页数、节数、总字数；
- 用了哪些 role（含 `metric`），预计出几张卡（贴 `--check` 的输出）；
- `script.json` 每卡的句数与预计时长；
- 哪些数字/专名你没把握（接手方会去核对）。

## 15. 常见被退稿的原因

1. 一节里塞两件事，卡面 120 字硬压。
2. 整组全是纯文字卡，视频里没有一处会动的东西。
3. 大标题里写了逗号，被引擎吃掉并乱断行。
4. 中文没写 `\n`，成图把词切开。
5. 卡面不到 30 字（45 字以下直接判 ✗）。
6. 口播一句 40 字，字幕切成三行还跟不上。
7. `script.json` 的 card 跳号，视频少一镜。
8. 抖音目的地没脱敏，出现厂商名或域名。
9. 写了 `role: "grid"`（图型 grid 不受影响）。
10. 封面纯文字没配图。
