# 文章配图规划（figure plan）：让 AI 先回答「这段该拍成哪张图」

这一步插在「读完文章」和「写 make.py」之间。它不产出图，只产出一份 **plan.json**：
每一张图为什么存在、它证明哪一句话、那句话在原文哪里、用什么图型、焦点给谁、哪些数字是推的不是原文的。

有了它，画图就变成执行，而不是临场发挥；也能被脚本审计（`plan_check.py`）。

---

## 一、输入

一篇已经定稿的 Markdown（不改原文），以及一句用户约束（比如「六张」「竖屏」「只画原文有的数字」）。

## 二、AI 要做的六步

1. **读完全文**。不是摘要、不是目录、不是前两节。选图型必须建立在全文读完之后的整体判断上：哪几段是真的在讲同一件事，哪几段只是同一节的背景。
2. **按原文的节切出 `article_map`**。用文章自己的标题切，一节一行，每行写 `section` / `claim` / `figures`（图 id 列表）/ `reason`（这节为什么不该画，只有 `figures` 为空时才要）。**这张表就是张数的来源**——作者写了几节、其中几节有证据，图就是几张。先数论断再估字数的做法是错的，那样 AI 等于没读。
3. **切论断**。把 `article_map` 里有证据的节切成「能被一张图证明的论断」。一个论断必须满足三条：能被数据或序列支撑；读者看完图会改变判断；删掉图这段就说不清。不满足的把整节改成空 `figures` 并写 `reason`。
4. **每个论断给 3 个候选图型，再挑 1 个**。候选必须写清四行：看见什么关系 / 为什么它比另两个合适 / 它会丢掉什么 / 画它的代价。`type_choice` 记下选中谁、否掉谁、为什么否——人被问到时可以直接换回去。
5. **写一句「为什么不是表格」**。表格或一段话能说清的，就不画。这一条挡掉大部分冲动。
6. **定焦点**。每张图只有 1 个（最多 2 个）焦点元素，回答「这张图要读者先看哪里」。
7. **标诚实边界**。凡推出来、不是原文给的数字，写进 `honesty_flags` 并说明怎么推的。原文没给的值，图上就要标。

## 三、规则（`plan_check.py` 会查）

| 规则 | 判定 |
|---|---|
| `anchor_quote` 必须能在原文里命中（忽略 Markdown 符号与空白） | 查不到 → fail（编了原文） |
| **块级覆盖**：每个 `figure: true` 的块必须被某页接住 | 漏一块 → fail，并印出行号与 claim；这是防「6 页覆盖半篇」的唯一闸 |
| 块的行号必须在原文行数内；块若写了 `anchor` 必须逐字命中 | 越界 / 查不到 → fail |
| 一页接的块 ≤ 3，同断言组放宽到 9 | 超 9 fail（拆页），跨组超 3 warn（一页在代替多页） |
| 每个数字都要在原文出现，否则必须在 `honesty_flags` 里标「推断 / 反推 / 原文未给」 | 漏标 → fail |
| **图数**由 `count_policy` 决定，不是常数 | `structure`（默认）要求 `article_map` 与 `figures` 对得上：每张图有归属、总数相等、不画的节写了理由，任一条不成立 → fail；`fixed` 用 `value` 定死；`split` 要求各卷图数之和等于实际张数，不等 → fail；`length` 是旧的按字数推区间，只作兼容 |
| 单张图 `budget.nodes ≤ 9`、`arrows ≤ 12`、`accents ≤ 2` | 越界 → fail（拆图，不是拆文章） |
| 图型必须在 `TYPES` 表里 | 不在 → fail |
| 必须写 `dropped`（至少 1 条） | 空 → WARN：说明你没做删减 |
| 同一篇里同一图型出现两次，每张必须写 `variant`，且**不许重样** | 缺写或重样 → fail |
| `type_choice` 写了候选与被否理由 | 缺 → 不判 fail，但缺了就说明第 3 步没做 |

### 图数的三种口径

```json
"count_policy": {"mode": "length", "density": [300, 600]}
"count_policy": {"mode": "fixed", "value": 12}
"count_policy": {"mode": "split", "batches": [
  {"name": "卷一 · 钱", "figures": 9},
  {"name": "卷二 · 组织", "figures": 11}
]}
```

20 张的稿子走 `split`：每卷是一条独立发布链（一组图卡 / 一段视频），卷内再按密度算。不要把 20 张挤在一张 `sheet.png` 里——缩略到看不清，等于没拼。


### 同型复用：形状必须真的不一样

一篇文章里有两段都适合时间轴，不能画两张一样的时间轴。`variant` 要写清「这张和那张的差别在哪」，不是改个标题就算：

| 图型 | 可用变体 |
|---|---|
| timeline | 断轴双层（前段放大、后段压缩）／单轨里程碑（等距表示顺序）／双轨对照（同一年的两条叙事）／甘特式持续段 |
| waterfall | 单向桥（只画下跌）／双向桥（有增有减）／带小计的桥／单位换算桥（亿元→百分比） |
| layers | 等高六层／厚度不等（按规模）／折角剖面（展开式）／带右侧注的层 |
| loop | 五站一环＋中央账本／三站小环（简化）／带时间轴的环（每圈标年份） |
| quadrant | 位置散点／情景矩阵（四格装命名方案，consultant 变体）／带密度的散点 |
| steps | 横轨等宽五段／竖列（窄栏）／带图标的横轨／带分支的步骤（退化为 flowchart） |

## 四、输出格式

```json
{
  "article": {"path": "…", "title": "…"},
  "count_policy": {"mode": "structure"},
  "article_map": [
    {"section": "一、…（原文标题，逐字）", "claim": "这节的可反驳结论", "figures": ["01-timeline"], "reason": ""},
    {"section": "二、…", "claim": "这节的可反驳结论", "figures": [], "reason": "并列清单，表格比图清楚"}
  ],
  "figures": [
    {
      "id": "01-timeline",
      "claim": "一句话，这张图证明什么",
      "anchor_quote": "原文原句，逐字复制",
      "figure_type": "timeline",
      "type_choice": {
        "chosen": "timeline",
        "candidates": [
          {"type": "timeline", "shows": "七年里事件落在哪一年", "why": "断轴能同时容纳前段密集与后段空窗", "loses": "事件之间的因果", "cost": "要两段不同比例并标注断轴"},
          {"type": "steps", "shows": "顺序，不显年份", "why": "最省事", "loses": "2020–2024 那四年空窗正是论点", "cost": "低"},
          {"type": "gantt", "shows": "每件事持续多久", "why": "能显示并行", "loses": "原文没有可信的起止月", "cost": "要编日期，不诚实"}
        ],
        "rejected_because": "steps 抹掉了空窗，gantt 需要原文没有的日期"
      },
      "reads_as": "读者第一眼看到什么",
      "why_not_table": "为什么表格/段落替代不了",
      "focal": "焦点元素",
      "budget": {"nodes": 8, "arrows": 0, "accents": 1},
      "honesty_flags": ["断轴：左段放大、右段压缩"],
      "data": [{"label": "2016.06", "value": "联盟峰会"}]
    }
  ],
  "dropped": [{"claim": "…", "reason": "…"}],
  "risks": ["这张图最容易被读者误读的地方"]
}
```

## 五、AI 提示词（可直接粘给任何模型）

> 你在给一篇中文长文规划配图。先**完整读完**全文（不是摘要），再动笔。不要写代码、不要画图，只输出一份 JSON。
>
> 1. 先按**原文自己的标题**切出 `article_map`：一节一行，写这节的可反驳结论、落到哪几张图；这节不该画的，`figures` 留空并写 `reason`。**张数由这张表长出来，不要按字数估。**
> 2. 把 `article_map` 里有证据的节切成「能被图证明的论断」；每条给原文原句（逐字复制，不许改写）、为什么表格替代不了、焦点在哪、哪些数字是推出来的。
> 3. **每条论断给 3 个候选图型**，每个候选写：读者看见什么关系 / 为什么合适 / 会丢掉什么 / 画它要付出什么（节点数、断轴、要不要标推断）。然后选出 1 个，在 `type_choice` 里写选中谁、否掉谁、为什么。只给一个选项的答案会被退回。
> 4. 图型只能从这份清单里选：timeline / waterfall / layers / loop / quadrant / steps / venn / bar / line / scatter / sankey / flowchart / tree / pyramid / heatmap / treemap / gantt / radar / delta / nested / state / sequence / architecture / swimlane / journey / dumbbell / unit-grid / story-map / fishbone。
> 5. 不要为了凑数加图，也不要为了整齐砍掉真论断。单套超过 12 张就分卷，在 `count_policy` 里写清每卷几张、讲哪一段。
> 6. 同一篇里同一种图型最多用一次；非用两次不可，必须写 `variant` 说明两张形状的差别（不是换标题）。
> 7. 表格或一段话就能说清的，写进 `dropped`，不要硬画。
> 8. 原文没给的数字，要么别用，要么在 `honesty_flags` 里写清「怎么推的」，并说明图上会怎么标。

## 六、这一套为什么好用

- **它把「配图」从审美问题变成证据问题**：图必须有原文句子撑着，AI 无法靠语感编一张漂亮但空心的图。
- **它挡住了图的通胀**：`dropped` 是强制字段，逼着 AI 明确说出哪些段落不值得画。
- **它把「诚实」变成了机器可查的字段**：反向推的数必须自己承认，否则校验不过。
- **它可以复用**：同一篇稿子换个模型跑，plan 一发散，diff 一眼能看出来。

## 七、下一步可接的东西

1. `make.py` 直接读 plan.json 生成页面（图型函数按 `figure_type` 分派），人只写数据。
2. plan 里的 `data` 字段可以加 `source` 行号，图上脚注自动生成。
3. 把 `dropped` 回灌给编辑：哪些段落其实没有可图形化的内容，可能是文章本身需要补证据。
