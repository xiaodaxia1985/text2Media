# 图型选型：50 种里我们真会用的那二十来个

diagram-design 有 50 种。下面按「读者该看见什么关系」分组，只留实战里用得上的，并写清「什么时候用它、什么时候换个更便宜的」。

选型顺序永远是：**先问关系，再问形状**。关系判断错了，画得再干净也是错的。

---

## 一、时间

| 图型 | 用在 | 别用在 | 我们踩过的点 |
|---|---|---|---|
| timeline | 事件在时间轴上的位置本身就是信息；间距不均可断轴 | 等间距的里程碑（那就退化成 steps） | 断轴必须左右比例不同并标注「断轴：两段比例不同」；轴上方别留 130px 空膛 |
| gantt | 任务有时长、有重叠 | 只是顺序（用 steps） | 别把 gantt 当甘特图表情包画 |
| lifecycle phase map | 一个主体经过阶段、等待、重试、终止 | 线性四步（用 steps） | 终止态要真的终止，不许悄悄回到第一步 |

## 二、量

| 图型 | 用在 | 别用在 |
|---|---|---|
| waterfall | 从起点到终点的**路径**：每根柱把上一层的余额推到下一层 | 只看两个端点的差距（用 dumbbell） |
| bar | 平级类目比较 | 有累积关系的（用 waterfall） |
| dumbbell | 两个值 + 它们之间的距离（前后对比、差距） | 中间发生过什么才是重点时 |
| line / slopegraph | 连续趋势；只有两个时间点且关心名次变化用 slopegraph | 三个点硬画成趋势线 |
| scatter | 两个变量相关、分布 | 四个点画成散点图（用 quadrant） |
| quadrant | 两轴定位、优先级、四个观察点 | 位置在格子内部才重要时（那是标准象限，不是顾问版） |
| unit grid | 一百个等大方格数出百分比 | 数值差异大（格子会撒谎） |
| heatmap | 交叉表，颜色填值 | 只有两列时 |
| pyramid / funnel | 层级递减、转化流失 | 并列类目 |

## 三、结构 / 层级

| 图型 | 用在 | 关键约束 |
|---|---|---|
| layers | 抽象层堆叠（OSI、技术栈、组织六层） | 6 层以内；层高一致；只在焦点层用 accent |
| nested | 包含关系（范围缩放） | 最多 4 层嵌套，再多就看不清 |
| tree | 父→子分解 | 别画成组织架构（那是 org chart） |
| architecture | 组件 + 连接，一个快照 | ≤9 节点；箭头正交 |
| **architecture delta** | 前后两套拓扑 + 变更账 | 左右**同尺度**；变更不超过 3–4 条；左栏若是作者的归纳必须在图注写明 |
| process | 多角色、有交接的多段流程 | 每个阶段要暴露 actor / 输入 / 输出，否则退回 steps |

## 四、流程 / 状态

| 图型 | 用在 |
|---|---|
| steps | 3–7 道有先后的工序，顺序就是论点 |
| flowchart | 有分支、有终点 |
| loop | 最后一站真的回到第一站，且中间有累积状态（hub） |
| state machine | 状态 + 迁移 + 守卫条件 |
| swimlane | 跨角色交接，责任归属是重点 |
| kanban | 各状态在制品与阻塞 |

## 五、关系 / 论证

| 图型 | 用在 |
|---|---|
| venn | 2–3 个集合的交集；交集才是论点 |
| fishbone | 一个结果的多类成因 |
| dependency | 谁依赖谁，有扇入/环 |
| wardley | 价值链 + 演化位置 |

## 六、方法

| 图型 | 用在 |
|---|---|
| steps | 方法、清单、路线（本 skill 里最常用的一张） |
| quadrant（顾问版） | 四个命名情景/赌注，格里写小段说明 |

## 三秒钟否决清单

出现下面任一情况，就别画这张图：

1. 一张三列表格能说明同样的意思。
2. 图上只有一个形状。
3. 读者要从图里读出「第几段最长」却用的是等宽方块。
4. 这张图删掉任何一个节点，结论就不成立了（说明它也撑不起结论）。
5. 你想在同一篇里画第二张同型图，但说不出形状上哪里不一样。
