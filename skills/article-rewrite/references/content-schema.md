# content.json 格式（v1）

`content.json` 只描述**内容和结构**，不含任何颜色、字体、尺寸。同一份文件可以用任意主题渲染。
写完后运行 `node ${CLAUDE_SKILL_DIR}/scripts/check.mjs content.json` 校验，不出图。

## 字数怎么算

本文档和 `figures.md` 里所有"≤ N 字"都按**视觉宽度**计：一个汉字或全角标点算 1，一个英文字母、数字或半角符号算 0.5。
例如 "YouTube 植入" 约等于 6 字。render 会按同样的规则给出超长提示。

## 行内标记

所有文本字段支持：
- `**加粗**`：页面上最关键的一句话加粗。每段最多 1–2 处。
- `\n`：强制换行，只在 `title`、`heading` 里用来控制断行。
- 其他 Markdown 和 HTML 都会按原样转义显示，不要用。

## 顶层

```jsonc
{
  "lang": "zh",                       // zh | en，影响"第 1 / 3 页""图 1A"等界面文字
  "theme": "paper-editorial",               // 主题名，或 {"long": "…", "cards": "…", "wechat": "…"} 分别指定。用户没指定时由你按 styles.md 来选；--theme 会覆盖它
  "title": "DAN KOE：2027 年\n最赚钱的 AI 生意",  // 每页顶部大标题，建议 2 行，每行 ≤ 12 个汉字
  "series": "实战手册 · 创作者经济",      // 页眉左侧的栏目名（可选）
  "source": {                          // 原文信息，用于页脚来源行
    "author": "Dan Koe", "handle": "@thedankoe",
    "title": "2027 年最值得做的 AI 生意",   // 原文标题（可翻译）
    "platform": "X 文章", "date": "2026-11-03",
    "url": "https://x.com/…"
  },
  "footnote": "…",                     // 可选。页脚小字；缺省会根据 source 自动生成
  "brand": { "name": "…", "handle": "@…" },  // 可选。页脚右侧的品牌名；缺省读 brand.json
  "pages": [ Page, … ]                 // 1–4 页
}
```

## Page

```jsonc
{
  "part": "第一部分 · 技能、市场与团队",  // 标题下方的彩色副标题
  "intro": "Dan Koe 是…第一页讲…第二页讲…",  // 2–3 句导语，可加粗；≤ 120 字
  "sections": [ Section, … ],          // 每页 3–4 节（checklist 节算 2 节）
  "closing": "**注意力是技能，品牌是留住它的东西。**第二页：访谈、挖掘、规划。"  // 页尾收束句 + 下一页预告；≤ 60 字
}
```

## Section（kind: "standard"，默认）

左栏是文字，右栏是两张图加一个数据面板。

```jsonc
{
  "label": "技能",                     // 显示为 "01 / 技能"，编号自动生成、跨页连续
  "heading": "注意力\n决定一切",          // ≤ 16 字，可用 \n 控制断行
  "paragraphs": ["…", "…"],            // 1–3 段，每段 ≤ 90 字
  "bullets": ["…", "…"],               // 0–3 条，每条 ≤ 30 字
  "takeaway": "无论你做什么，能不能卖出去都由注意力决定。",  // 一句收束金句，≤ 26 字
  "figures": [ Figure, Figure ],       // 0–2 张，推荐正好 2 张；类型见 figures.md
  "panel": Panel                       // 可选，图下方的彩色底面板
}
```

## Section（kind: "checklist"）

整页宽度的阶段清单，适合"行动清单 / 执行步骤"，通常放在最后一页的最后一节。

```jsonc
{
  "kind": "checklist",
  "label": "执行",
  "heading": "创始人执行清单",
  "paragraphs": ["按实际执行顺序排列。**从上往下做；事情真做完了才打勾。**"],
  "stages": [                          // 2–6 个阶段，两列排布
    { "label": "第 1 阶段", "title": "定下打法",
      "items": ["选一个：做你自己的品牌，或做别人的创意团队。", "…"],   // 每个阶段 2–5 条，每条 ≤ 30 字
      "done": "你能用两句话说清它为谁而做、为什么是你。" }               // "做完的标准"，≤ 30 字
  ],
  "guard": {                           // 可选：深色"护栏"卡片；items 必须是原文点名的失败模式，原文没有就不写整个 guard
    "title": "该避开什么",
    "items": ["别把它当一夜暴富。", "…"],
    "note": "每一条都是他文中点名的失败模式。"
  },
  "note": "步骤和数字是他的；阶段划分和顺序出自编者。"   // 可选，清单下方的小字说明
}
```

## Section（role：这一节是什么）

`role` 声明这一节在论证里承担什么，卡片（image-cards）据此换整张卡的版式，不再每节都排"标题 + 正文 + 图"。**不写 role 时引擎会按标题句式猜**，猜不准就退化成常规卡；写了但没写对应内容，也只退化，不会报错。

| role | 卡片长什么样 | 需要写的内容 | 容量上限 |
|---|---|---|---|
| `claim` | 一句大主张占满卡，短线 + 一句补充 | `claim.text`（不写就用 `card.text` / 第一段） | 主张 ≤ 25 字 |
| `compare` | 左右两栏，各栏一条细线 | `compare.left / right` 各有 title + items | 每栏 2–4 条，每条 ≤ 14 字 |
| `timeline` | 纵向节点，只靠细分割线分隔，不写序号也不放圆点 | `timeline`：`{at, title, note}`；`at` 只写真实时间（第 3 天 / 3 月），顺序已由位置表达 | 3–6 个节点 |
| `stat` | 1–3 个大数字，口径小字 | `stats`：`{value, unit?, label, note?}` | ≤ 3 个数字 |
| `opener` | 幕标（这一部分叫什么）+ 章节标题 + 一条短线 + 一句导语（居中，不写节序号） | 只用 `heading` + 第一段 | 标题 ≤ 10 字，留白 ≥ 40% |
| `fig` | 图卡证据：图自己占卡高 45–65%（不缩成小配图），说明压在下方，有数字就排一行小号数字 | `figures` + `card.text`（说明）+ 可选 `stats` | 说明 ≤ 40 字；数字 ≤ 3 |
| `process` / `evidence` / `quote` / `structure` / `checklist` | 仍走常规卡 / 图卡 / 清单，role 只在 `--plan` 里参与节奏统计 | — | — |

界格 `grid`（一字一格）已于 2026-11-11 下线：一列一个字在中英混排的正文卡上读起来像空表格，写了会直接报错。原「四个前提」这类并列短词，改写成 `claim`（一句判断 + 一句补充）或直接并进相邻卡。

```jsonc
// 主张：一句话就是一张卡
{ "role": "claim", "label": "主张",
  "claim": { "text": "纯静态站的问题\n不是怎么做，是放在哪。", "note": "跑一次 build 就出一个 dist 目录。" } }

// 对比：≤5 维，不要色块，用一条细线分开
{ "role": "compare", "label": "对比", "heading": "两台托管，差在哪",
  "compare": { "left": { "title": "Cloudflare", "items": ["部署没有问题", "国内打不开"] },
               "right": { "title": "EdgeOne", "items": ["部署同样顺利", "国内可访问"] },
               "note": "差别不在配置，在可达性。" } }

// 时间线：at 只在有真实时间时写；没有就留空，靠圆点和位置表达顺序
{ "role": "timeline", "heading": "上线四步",
  "timeline": [{ "title": "仓库里构建", "note": "npm run build 出 dist" }] }

// 数据：数字是版面主角，口径必须写清
{ "role": "stat", "heading": "两套时间尺度",
  "stats": [{ "value": "按天", "label": "验证周期", "note": "上线当天就有反馈" }] }

// 章节页：只留编号、标题、一句导语；不要正文和图
{ "role": "opener", "heading": "先上线\n再补票", "paragraphs": ["服务器和备案，等验证成立之后再补。"] }
```

**一条硬规则**：卡型自带容量上限，超了就拆卡或改 role，不要靠缩字号塞进去。一组卡片（3:4）建议 10–12 张以内，每 3 张至少一张"轻卡"（claim / opener）。

**下限同样是硬规则**：一张卡（主张/章节页之外的）如果只有一句话，会读成"头重脚轻的大留白"。凑不够 30 字就**改内容结构**——把相邻两个薄节并成一张卡，或补一句说明/一个数字，不要指望版式去填。2026-11-12 起渲染期按 45 字判薄（覆盖率 <78% 会报提示）：30 字是底线，45 字才排得满。

## 出处：evidence / source / span

每一节都可以声明"这页的证据是什么形态、它出自原文哪一句"。写了就校对，写不成立就是抄错。

```jsonc
{ "role": "stat", "label": "验证", "heading": "十二组样张\n零错误",
  "evidence": "number",                       // none / compare / step / list / number / quote / image
  "source": "四套主题配上长图、3:4 和 9:16 三种比例，一共十二组，版面检查 0 个错误。",  // 原文原句，一字不改
  "span": { "start": 1420, "end": 1490 },     // 这句在 article.md 里的字符偏移
  "stats": [ … ] }
```

- `span` 由 `engine/scripts/lib/outline.mjs` 从原文里抽出来（`node outline.mjs article.md --out 目录` → `outline.json`），不要手工填。
- 校验：`span` 指向的原文必须包含 `source`，对不上直接报 ✗（出处抄错了）；只写 `span` 不写 `source` 会提示"无法核对"。
- `evidence` 是"这页能拿出什么"，不是"这页叫什么"：`number` 指真的有成组数字（≥2 个，或带 %/倍/组/套/种），只有一句"出了第一套图"不算。
- 一节的 `span` 能连到原文，这一组图才敢说"没改原作者的意思"；span 缺失不影响渲染，但交付时要说明哪些页没有出处。

## Panel

三种类型，统一放在图的下方。标题写法：`<这是什么> · <出处>`，例如"他的数字 · 编者核对""可以试的提示词 · 他的原话""两种账号 · 编者归纳"，让读者分清原文和编者加工。

```jsonc
// 1. 表格：2–5 行，左列是短标签（≤ 10 字），右列是解释（≤ 50 字）
{ "type": "table", "title": "谁在为注意力买单 · 他的看法",
  "rows": [["你自己的生意", "发内容现在几乎是吸引付费受众的标配"], ["…", "…"]] }

// 2. 卡片：2–9 张，自动排成 2 或 3 列；text 可以是引语
{ "type": "cards", "title": "两种账号 · 编者归纳",
  "items": [{ "title": "内容还行，没有品牌", "text": "一条爆了，之后每条一千播放。" }, { "title": "…", "text": "…" }] }

// 3. 引用：一大段原话（提示词、关键引文），≤ 160 字
{ "type": "quote", "title": "可以试的提示词 · 他的原话",
  "text": "“从 [@handles] 抓取最好的内容……”", "note": "注：他用自家工具 Eden 来跑；只要你能把帖子喂给模型，用什么都行。" }
```

## Figure（通用字段）

```jsonc
{ "type": "bar", "caption": "美国品牌在创作者上的投入：五年约涨 3 倍。", "note": "IAB · *预测值", … }
```

- `type`：图表类型，见 `figures.md`。
- `caption`：图下方的说明，≤ 24 字，说出"这张图想让读者看到什么"，而不是复述图名。
- `note`：图内底部的小字（数据来源、单位、"示意图"等），≤ 20 字，可选。
- 其余字段按类型而定。

## 卡片专用字段（可选）

只影响卡片（image-cards，`--ratio 3:4 / 4:5 / 1:1 / 9:16`），长图会忽略它们。写法和取舍见 `../../image-cards/references/xhs-guide.md`。

```jsonc
{
  "cover": { "title": "…", "kicker": "…", "subtitle": "…", "points": ["…"], "summary": "…", "cta": "…" },
  "xhs": { "title": "≤ 20 字", "caption": "≤ 1000 字", "tags": ["…"] },
  "pages": [{ "sections": [{
    "…": "…",
    "card": { "mode": "single|split|skip", "text": "…", "bullets": ["…"], "figure": 0, "panel": false }
  }] }]
}
```

## 公众号专用字段（可选）

只影响导出的文章 `rewrite.md`（`export.mjs`），也就是公众号总结用的标题、摘要和头图。写法见 `../../wechat-layout/references/wechat-guide.md`。

```jsonc
"wechat": {
  "title": "≤ 64 字",          // 公众号标题；缺省用 title
  "digest": "≤ 120 字",        // 摘要（分享卡片上那行字）；缺省用第一页导语
  "coverTitle": "…",           // 可选：头图上的标题，缺省用 title（保留 \n 断行）
  "kicker": "…"                // 可选：头图上方小字，缺省用 series
}
```

## AI 插画（可选）

用户要插画时才写，生成方法见 `figures.md` 的 illustration 一节。

```jsonc
"cover": { "…": "…", "illustration": { "prompt": "画面描述（英文更稳）", "aspect": "4:3" } },  // 封面插画：长图第一页标题旁、小红书封面、rewrite.md 的题图（公众号题图和头图）
"illustration": { "style": "…" }   // 可选：统一指定画风，覆盖主题自带的画风
```

## 页数与密度建议

| 原文长度 | 页数 | 每页节数 |
|---|---|---|
| < 1,500 英文词 / 3,000 汉字 | 1 页 | 3–4 |
| 1,500–3,000 词 | 2 页 | 4 |
| > 3,000 词 | 3 页（最多 4 页） | 3–4 |

每页渲染出来高度应在 2,600–4,200 px（CSS 像素，宽 1,200）之间；render 会在超出时提示。
