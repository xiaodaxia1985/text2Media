# 系列长文精读卡片（series-reading-cards）

## 这套东西解决什么

外文长文直接翻译发出去，读者看完记不住；只发解读，读者又会问「原文到底说了什么」。
所以先定模式，再排页：**先立人（封面）→ 原文精读（只译述，不掺判断）→〔可选〕我们的判断 → 全文要点（可收藏）**。

## 第一步：先判模式，再定张数

| 模式 | 什么时候用 | 结构 | 3:4 典型张数 |
|---|---|---|---|
| **A 纯精读** | 用户只说「翻译成中文 / 做成卡片 / 整理原文」，或素材是别人的文章、没有任何自己的笔记 | 封面 + 原文 + 结尾 | 12–20 |
| **B 精读 + 判断** | 用户带自己的笔记、观点，或明确说「加上我的看法 / 我们的判断 / 系列栏目」 | 封面 + 原文 + 判断 + 结尾 | 18–30 |

判定顺序：
1. 看用户话里有没有「我的看法」「我们补的」「判断」「点评」——有就是 B。
2. 看素材里有没有自己的笔记、录音、草稿、大纲——有就是 B。
3. 都没有 → **默认 A**，不要给别人的文章硬塞观点。
4. 两种都说得通、且这次是要对外发布的，问一句就够：**这组只讲原文，还是后面加我们自己的判断？**（不要为此列一堆题）

### 张数由内容算，不从平台上限倒推

1. 把原文拆成「信息块」：一个论点 / 一个方法 / 一个岗位 / 一组清单步骤，各算一块。
2. 一块一张。装不进就 `split` 成两张；内容太薄（<45 字）就和同主题的邻块并。
3. 清单类按 5–6 个阶段 / 张计。
4. 判断段：B 模式 4 张（转折 + 按层拆 + 我的进度），要压缩时并成 3 张；A 模式 0 张。
5. 加封面 1、结尾 1，得到总数。
6. **最后才过平台上限**：超了按下表压，不删原文方法；不到 12 张说明块拆得太粗，回头拆细。

| 压缩阶梯（超上限，按序用一档重算一次） | 扩展阶梯（张数太少但内容够） |
|---|---|
| `split` 两页合一 | 判断段每层独立成卡 |
| `mode:"skip"` 与后节重复的节 | 清单 / 图表单独出卡 |
| 判断段并张（5→3） | 关键原句单独出 `quote` 卡 |
| 仍超：拆成两条发布，各自带封面与结尾 | |

## 平台

| 平台 | 比例 | 尺寸 | 单篇上限 | 说明 |
|---|---|---|---|---|
| 小红书 | 3:4 | 1080×1440 | 18 | 超了压卡，不是删内容 |
| 抖音 | 3:4 | 1080×1440 | 30 | 交 9:16 会被套框裁边 |
| 微信 | 3:4 | 1080×1440 | 9 | 长文排版另走 wechat-layout |
| X | 4:5 | 1200×1500 | 4 | 信息流竖图 |

渲染入口（`<repo>` 指工具链仓库根，如 `text2Media`）：

```bash
node <repo>/skills/image-cards/scripts/cards.mjs <目录>/content-<平台>.json --platform 小红书
```

产物：`<目录>/<主题>-<平台>-3x4/` 下的 `card-01.png…`、`overview.jpg`、`frame-check.png`、`caption.md`。
**一个平台一份 content.json**，公用母本另存 `content.json`，不要在一个文件里反复切主题。

## 主题

- 默认 `apple-hark`；同一系列跨平台固定同一主题，读者在信息流里认得出你。
- **封面带真人照片时只能用浅色主题**：照片白底压到 `hark-noir` 这类深色底会变成一块白色椭圆光斑。要用深色，先把照片抠成透明 PNG 再进缓存槽。
- 改品牌色只动 `--accent-2`，同步 `--accent-4` / `--accent-6` 为同色相深浅阶；`--accent-1` 保持黑（深色主题保持白）。

## 封面：立人 + 原标题

```jsonc
"cover": {
  "title": "国外大神\n<作者> 新作\n<原文标题换行>",      // 每行 ≤10 字，2–4 行，**…** 标一个关键词
  "kicker": "<作者> · X 长文精读",                      // 别和标题重复
  "subtitle": "…",                                     // ≤60 字：先身份背书，再一句激励
  "illustration": { "prompt": "…", "aspect": "4:3" }    // 一旦有图就丢掉 points/TOC，只剩 kicker/title/图/subtitle
}
```

- **署名效应大于一切**：封面必须出现「国外大神 + 作者名 + 原文标题」。这是认可度来源，不要换成抽象金句。
- 副标题结构：`作者的硬身份（粉丝量/产品/连续年限）` + `方法他全摊开了，差别只在照着做，还是只收藏。`

### 真人照片进引擎（不让 AI 造像）

引擎插画 prompt 写死「Do not depict real, identifiable people」，真人图只能从缓存槽喂：

1. 作者官方站点或公开访谈里的正脸照，存成 `<目录>/../<作者>-portrait.jpg` 这类稳定路径。
2. 按内容的 `theme` 和 `cover.illustration` 算缓存 key（`keyFor(prompt, style, aspect, kind)`）；**每个主题 key 不同**。
3. copy 成 `<目录>/illustrations/<key>.jpg`，重渲染即自动读取；`EXTS` 含 `png`，抠好的透明图存 `<key>.png` 优先命中。

## 单卡规则（引擎硬约束）

- 一卡一事。`card.text` ≤90 字，`bullets` ≤3 条、每条 ≤26 字。
- **纯文字卡一定被判「整段空白」**：每节必须有图，或 `panel` —— 且 `card.panel: true` 才渲染。
- **A 模式**：原文段一个字都不许掺判断词（「我认为」「其实」「关键是」）。
  **B 模式**：判断只出现在判断段，原文段同样干净。
- 大标题不带逗号句号；要断得干净就自己写 `\n`。
- 超上限按「压缩阶梯」走，**不删原文方法**。

## 判断段（仅 B 模式）

一卡一件：转折（`compare`：他讲的 vs 他跳过的）、按层拆（每层一张 `stack`）、我的进度（`stack`：我有什么 / 卡在哪）。
小红书要压时，把「按层拆」合成一张三块 `panel`（01 条件 / 02 机会 / 03 最小产品，各一句话）。
A 模式没有这一段，结尾卡也**不要**出现「我的判断/补的三层」这类字样。

## 结尾卡

`cover.summary` 一句大字（自己写死 `\n` 断行），下面两栏列每节 `takeaway`。
**必须偶数条、每条 ≤14 字单行**，否则两栏长短不齐对不上；超过 16 条先合并节。
A 模式只有原文节的 takeaway，条目数按实际算，同样必须偶数。

## 禁止项

- 手排白底卡、任何不套主题的版式。
- 收入数字、粉丝总量、报价区间（原文有且已核实才可写，并标「原文引用，未经核对」）。
- AI 生成原作者肖像。
- 把卡片拆成「原文组」「理解组」两组分开发 —— 同一组里揉着排。
- 给没有观点的素材编一段「我们的判断」。

## 交付前强制核对

出图后**先跑脚本再交付**，不要用肉眼数卡：

```bash
node <skill>/scripts/verify_delivery.mjs --content <目录>/content-<平台>.json --dir <产物目录> --platform 小红书
```

它逐项断言：卡文件连续且不超平台上限；`caption.md` 的张数与卡号区间自洽（出现「前 N 张」这类没有卡号的裸数字直接报错）；按模式核对总张数（A 模式 `N = 1 + 原文 + 1`，B 模式还有判断段）；**A 模式的文案里出现「判断/我的看法」直接报错**；结尾图片行与总张数一致；`overview.jpg` / `frame-check.png` 比最后一张卡新；结尾 `takeaway` 为 0–16 的偶数；小红书标题 ≤20 字符。
任何 ✗ 不许交付，改完重跑直到全 ✓。

**⚠ 不等于可发**：逐条判。「整段空白 / 空带 >15%」补内容或换卡型；「靠收字号才装下」说明已到容量上限、别再往里加字；最多两轮，第二轮仍报的写进交付说明。

## 系列复用

新一期：换作者名、原文标题，再按第一步重判 A / B 与张数，版式与约束不动。
目录按 `output/<日期>/<渠道>/<系列名>/`，母本 `content.json` + 各平台 `content-<平台>.json` + `illustrations/` 同目录保存。
