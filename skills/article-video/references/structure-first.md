# 结构件先行（每镜必须有一个图形主体）

> 2026-11-19 定版。起因：01 集竖版骨架第一版「十几镜全是字 + 一条细线」，用户评价「好几个页面都显得太空，通篇都是文字来表述，画面没有结构，没有组件」。
> 根因不是字排得不好看，是**每镜没有结构件**——只有排版，没有图形。本文件把这条做成硬判据，出骨架前逐镜过一遍。

## 0. 一句话

**先决定这一镜的图形主体长什么样，再让文字去给它做注。** 反过来（先把话说上去、再想办法填空）必然空。

## 1. 四条硬判据（不过就不许进静帧批）

| # | 判据 | 怎么量 |
|---|---|---|
| J1 | **每镜必须有一个结构件**（卡 / 矩阵 / 刻度尺 / 双栏 / 关系图 / 大数字 / 人像 / 引文块 / 流程段） | 组件里能指出那个元素；只有一个 `Huge` + 一条 `Rule` 的镜头 = 不合格 |
| J2 | **结构件高度 ≥ 内容区 1/3** | 竖版 1080×1920：内容区 y 200–1660（1460px），结构件 ≥ **480px**；16:9 按 720 高的内容区取 ≥240px |
| J3 | **上下都要触到**：内容区下 1/3（竖版 y≥1180）不许整片留白 | 镜末帧量「y 1180–1660 的非背景像素占比」，< 6% 记 FAIL |
| J4 | **文字层数 ≤ 2**（标题 + 注），其余信息必须进结构件 | 数一遍：同一镜里独立成行的文字块 ≤2 组 |

补充（来自 a2e `composition-and-light.md` §1，原话）：
> 每个镜头有一个占内容主区高度 ≥1/3 的主体——图形 ≥170px 高，或大字/大数字 ≥96px 且整行宽 ≥300px。

**大字不算结构件**。大字 ≥96px 只满足「主角尺寸」，不满足「画面有结构」——一屏全是大字照样空。

## 2. 结构件清单（竖版纸面语言，图元在 `engine/src/epbase/ed.tsx`）

| 图元 | 长什么样 | 用在哪 |
|---|---|---|
| `Panel` | 1px 细线框 + 极淡底（`#FAFAF8`），无圆角无投影，可带卡内小标签 | 来源卡、引文卡、证据卡、能力清单、任何"内容装进一个框里"的镜 |
| `Meta` | 卡内元信息行：左灰标签 + 右值，两列对齐 | 署名、平台、计数、口径 |
| `Glyph` | 线框图标（doc / user / coin / check / cross / ask / eye），1.5px 线条 | 卡内的图形主体、关系图的节点 |
| `Scale` | 等距刻度尺 + 当前刻度实心 | 量级、进度、13 集序列、时间轴 |
| `BigNum` | 细体巨数字 + 单位 | 量级、编号、集数 |
| `Row` | 编号行（细线分隔 + 左编号 + 右符号） | 台账、清单、对照 |
| `Serif` | 宋体大字 | 只给原文金句与集末判词（每集 2–3 处） |
| 自绘图 | 双栏、矩阵、关系图（连线 + 节点 + 问号） | 见下节关系表 |

## 3. 句子关系 → 结构件（按"这句在说什么关系"选，不按"有没有数字"选）

| 画面关系 | 结构件画法 |
|---|---|
| 一个人物 / 一方身份 | **人物卡**：头像 + 名字 + 2–3 条元信息 + 一个巨数字 |
| 一份来源（文章、论文、文件） | **来源卡**：封面行 + 标题 + 作者/机构/平台 + 形态 + 一条刻度或计数 |
| 一句引文（要强调出处） | **引文卡**：大引号 + 宋体金句 + 署名线；可先出空壳（占位横线）再填满 |
| 一个主张 + 若干依据 | **证据链**：编号空格 ①②③ 先立起来，逐个点亮/填充 |
| 缺了什么（判据缺失） | **空格**：虚线框 + 问号，明确是"没填"不是"没画" |
| 凭什么（因果、交易） | **关系图**：左节点 → 断开的箭头 + 问号 → 右节点 |
| 两条路 / 两类人 | **双栏**：两栏同高并置；第二栏比第一栏晚立起来 |
| 两条路汇到一处 | **汇合**：两栏底部各出一条线，汇到中心圆（承接双栏的同一几何） |
| 两层意思 / 分层 | **分层带**：两条横带错位半个身位，编号 1/2，讲到哪层哪层放大 |
| 三件事 / 清单 | **台账**：编号行三行，行高 ≥150 |
| 很多 / 序列 / 13 集 | **矩阵** 或 **刻度尺**：格子按节拍点亮，不许撒碎屑 |
| 量级 / 数字冲击 | **巨数字** + 单位 + 一个对照物（另一数字或图标） |
| 时间 / 过程 | **流程段**：输入盒 → 处理器盒 → 输出盒 + 箭头 draw-on |

## 4. 承接：连续镜共用同一套几何

长片不是 20 张独立海报。**同一套结构在两三镜之间演化，观众才看得见"结构在动"**：

- 空壳 → 填满（引文卡 04→05）
- 单栏 → 双栏 → 汇合（10→11→12）
- 分层带立起 → 第 1 层展开 → 第 2 层展开（14→15→16）
- 编号空格 → 逐格点亮（06→07→08）

做法：**坐标写死复用**（同一 `Panel` 的 y/h、同一中心圆的 cx/cy），只改"填了什么"。

## 5. 出骨架前的自检脚本

渲完镜末帧后跑两条量化（不靠眼睛）：

```powershell
# 1) 下 1/3 留白检查（J3）
# 2) 结构件高度：内容区最大连通块高度（J2）
python .tmp\frame_structure_check.py <静帧目录>
```

阈值（竖版 1080×1920）：
- 下 1/3（y 1180–1660）非背景像素 < 6% → FAIL
- 最大连通块高度 < 480px → FAIL
- 全帧非背景像素 < 4% → FAIL（等于纯字）

## 6. 反例（本项目实际踩过）

- 01 集第一版：20 镜里 16 镜「大字 + 一条细线」，内容区墨占比 1.3–2.7%，下三分之一整片空着 → 用户一句「通篇都是文字」判掉。
- 上线前拿它当判据：只要有镜头的画面能一句话说完「上面一行大字，下面一条线」，就是不合格。
