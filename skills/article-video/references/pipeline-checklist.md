> 这份不是参考文档，是**执行协议**。用户说「用这套 skill 出一支视频 / 这篇文章出个视频 / 按老套路出片 / 文章转视频」时，第一动作就是读本文件并按 P1–P9 推进。

> 底座：`anything2explainer`（下称 a2e）——**一镜一组件**，版式就是 `SCxx.tsx`，import 进 Main 即必然进画面。2026-11-18 起 talkcraft 卡池路线整体作废。

## 执行协议（每次触发，先照这六条）

1. **触发即建待办**：命中触发词后，用 `task_create` 把 P1–P9 建成任务清单，每段一个任务；进入某段 `task_update → in_progress`，走完 `→ completed`。**不许无任务列表地直接开干。**
2. **逐段推进，不许跳段**：上一段出口条件未满足，不许开下一段。尤其不许「稿子还没审就先渲」。
3. **三个审批点必须弹窗**：P2 口播稿、P3 骨架联系表、P6 静帧批。到点**必须调用 `interaction_ask`** 弹审批卡，不许只在正文里问一句「你看行吗」。
4. **弹窗选项固定三项**：`通过` / `退回修改` / `暂停`。用户选 `通过` 才允许进下一段。
5. **审批留痕**：每次弹窗的结论回填文末「审批台账」。
6. **反馈节奏（用户 2026-11-18 定）**：待办全程挂在会话，中途被打断也不撤。每段开始/结束各报一句；**单步预计 >10 分钟先报预估再动手**；实际跑 >30 分钟无结果必须停下报「卡在哪、还剩多少、要不要换法」，由用户决策，不许闷着跑。

## 第 0 条 · 铁律（优先级高于本文件其余全部内容）

1. **遇到问题，先查官方文档 → GitHub 仓库/issue → 社区成品**，确认「别人已经怎么解决」，再动手。
2. **不许自造轮子**。Remotion 已有 `renderFrames` / `renderMedia` / `frameRange` / `combineChunks` / Studio；先用这些。a2e 已有图元库 `ui.tsx`、光效 `fx.tsx`、配音 `tts_build.py`、体检 `frame_metrics.py` / `motion_check.py` / `selfcheck.py`；先用这些。
3. 确实查不到、必须自建时：**先说明「查过哪几份文档、为什么都不适用」，等审批后再写**。
4. **不确定就停**：宁可停在「图已出、等你点头」，不许闷头往下渲。
5. **长句必须切短句**（≤22 字/段）：超过 22 字配音会断错位、帧号会全错、画面必崩。这是硬规则不是建议。
6. **一镜一组件，不建卡池**：每镜的版式是一个独立 `.tsx`，为一句话现画。禁止「先造 47 张卡再往里填 props」——内容是变的，卡是死的，必然「内容迁就卡」。也不许自建 `atoms.tsx` / `families.tsx` 充当版式（本项目已因此被推翻两版）。

**为什么 6 是硬的（实证，勿重犯）**：47 镜那版的路径是「读别人的卡 → 归纳成 10 类版式 → PIL 画 47 张 PNG 定妆 → React 用 15 个图形原子重画一遍」。中间没有一行 `import`，全靠人肉翻译，间距/字阶/装饰/层级在翻译里全丢，成片成了「几何形状 + 一行字」。结论：**骨架不在工程里，就一定不在画面里**。

### P6 三条硬判据（2026-11-18 第一章从零重跑得出）

以前这三处都靠"渲完看片子觉得怪"才发现，现在前置成静态检查，一次静帧就能抓：

1. **0.8s 帧不许是空壳**。每镜首帧必须已经站着主结构——卡片里要有线、九宫格里要有多数格、路径上要前三块都在。**首批元素一律从 `f+2` 起步，不许排到 `f+30` 以后**。判据：首帧里主力图形不能只剩一个空轮廓。（第一章实测：DK02 卡片翻开时是空的、DK04 访谈卡只有 1 条线、DK05 只出 6 格、DK06 第三块还没进，四项全中。）
2. **进度驱动的长度，为 0 时不许留痕**。线 / 条 / 柱按 `progress × 全长` 算宽度时，端点装饰（竖线、箭头、圆点）必须 `progress > 0` 才显形；否则画面会凭空多出两根悬空竖线。（DK07 实测两条孤立竖线。）
3. **标签左边界 ≥96**。居中文字按 `cx − 字数 × 字号 / 2` 反算左边界；低于 96 就把整组（标签＋线起点＋末端标注）一起右移，**不许靠缩字号硬塞**。（DK07「这几个答案」32px 五字，中心 128 → 左边界 48，已贴边。）

## P7 · 整片渲染（首选 `renderMedia`，出片前 30 秒必做完整性自检）

> **2026-11-18 实测定论（根因已查死，别再从路径/并发/管道上试错）**：渲染卡在 ~50% 不是路径、不是并发、不是进程被杀，
> 而是 **`node_modules` 所在目录被打成低完整性级别（`Mandatory Label\Low Mandatory Level`），同时树上还挂着 `Everyone:DENY(S,DC)`**。
> 从这种目录启动的程序会被降为**低完整性进程**，只能写低完整性对象；C 盘 TEMP、E 盘普通目录都是中完整性，
> 于是 Remotion 内置的 `ffmpeg.exe` 每次打开输出文件都 `Permission denied`，`renderMedia` 渲完帧后卡在编码端，
> 最后抛 `write EOF`——表现出来就是"一跑就出大问题、总跑不顺"。
> **换 TEMP 路径、改并发数、去掉 shell 重定向全部无效**，它们都没碰进程的完整性级别。
> 修好之后同一个 `renderMedia` 一步出片：1354 帧 / **58.7 秒** / 2.76MB / 45.18s / 1280×720 / 立体声 aac。

| # | 做什么 | 出口条件 |
|---|---|---|
| 7.0 | **完整性自检（30 秒，必做，不许跳）**：`icacls "<工程>\node_modules\@remotion\compositor-win32-x64-msvc"`，看有没有 `Mandatory Label\Low Mandatory Level` 或 `DENY`。有 → 先做 7.0b，**不许直接开渲** | 无 Low IL、无 DENY |
| 7.0b | **根治（不需要管理员权限）**：①在**项目根**（未被降级的那一层）建 `.runtime\node_modules`；②`robocopy <旧node_modules> <新目录> /E /COPY:DAT /R:1 /W:1 /MT:16`（`/COPY:DAT` **不带 SEC**，新文件才继承 Medium）；③旧目录改名 `node_modules_low_bak` 留备份；④`mklink /J <工程>\node_modules <新目录>`；⑤用**工程原路径**下的 ffmpeg 往 `%TEMP%` 写一个测试 mp4 验证 | ffmpeg 能写 C 盘 TEMP |
| 7.1 | **一步出片**：`tools\t2m-video\render.ps1 <Comp> out\<id>.mp4` —— `bundle` → `selectComposition` → `renderMedia`（`codec:'h264'`、`imageFormat:'jpeg'`、`concurrency:16`、`chromiumOptions:{gl:'angle'}`） | 出 mp4；`encoded` 从 0 一路涨到总帧数，`stage=muxing` 后 DONE |
| 7.2 | **兜底（仅当 7.0b 不可行时）**：`renderFrames` 出 JPEG（文件名**四位补零** `element-%04d.jpeg`，写成两位会报 `No such file`）+ 系统 ffmpeg 编码混音。这是 Remotion 官方支持的另一条路径，不是自建轮子 | 同 7.1 |
| 7.3 | 日志由 node 自己 `fs.appendFileSync` 写；进度按 `progress / rendered / encoded / stage` 四项打点 | 每秒都有新行 |
| 7.4 | **异常判定**：连续 1 分钟 `encoded` 不增长（哪怕 `rendered` 还在涨）＝ 编码端写不了文件，立刻停下查 7.0 | 不许干等，不许闷跑 |

| 7.6 | **垫乐**：`tools\t2m-video\mix_bgm.ps1 -Video <整片> -Bgm <wav> -Out <整片_music.mp4>`（默认 -13 dB、淡入 2s、淡出 3.4s） | 混后 `ebur128` 积分响度与无乐版一致 |

**片头片尾与页脚/垫乐的硬规则**（2026-11-19 定，详见 `references/brand-bookends.md`）：只用自有圆环台阶标记、不放人物照片；卡框与圆环先立住，台阶再一级一级升起；**页脚不许有页码与总页数**；垫乐比旁白低约 20 dB、混后 LUFS 不许变。

## 一页速记（贴在开工处）

```
读本文件 → 建待办 P1-P9 → 查文档(≥3 URL)
        → P1 参数卡（文章/画幅/时长档/语言/音色）
        → P2 稿子 + vo_check + 去AI味 + 大字      🚦弹窗①
        → P3 一镜一组件 + 10-14 帧联系表          🚦弹窗②
        → P4 配音 → 归一 → 切 audio.wav → 折帧号
        → P5 分镜表 + Composition + tsc
        → P6 静帧批 + 九项体检                    🚦弹窗③
        → P7 tools\t2m-video\render.ps1（jpeg+angle+16并发，卡住就报）
        → P8 ffprobe + 逐帧体检 + 抽帧复查
        → P9 归档 + clean.ps1 清 .tmp\rt + 回填台账
```

**三条最容易忘、代价最大的**：
1. **长句不切 = 配音错位 = 帧号全错**。稿子阶段就切到 ≤22 字。
2. **骨架不在工程里 = 画面里一定没有**。每镜独立 `.tsx`，import 进 Main 才算数。
3. **渲染卡住不许等**。5 分钟无进展就停下查进程和 CPU，报用户决策。

**P6 三条判据记成一句话**：首帧不许空壳（元素 `f+2` 起）· 零长线不留痕（装饰 `p>0` 才显形）· 标签左边界 ≥96（超了移整组，不缩字号）。
