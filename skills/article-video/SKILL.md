# Article Video

一支图解短片就三件事：**这十镜分别讲什么、每镜用哪种图文关系、字是谁写的**。三件都不该临时拍脑袋：
镜次来自文章结构，图文关系来自这一镜在干什么，屏幕大字来自 plan 里已有的 `claim`。

**这个 skill 只做「构图 + 出帧 + 交给渲染」，不重新画图。** 页由 `article-figures` 出（已经验收过的那十页就是素材），也可以是任何同纸色的自建页；两条线**只共享输入文章**，不要求出图时顺便把页做成竖屏——那是让两边互相凑合。

## 一、五步

| 步 | 命令 | 产物 |
|---|---|---|
| 0. 写口播稿（**最重要，稿子不过不许往下走**） | 按 `references/voiceover.md` 写，然后 `python scripts/vo_check.py talk.json --subject <主角名> --article <原文.md>` | `talk.json`（每镜 `id / headline / line`）＋ 0-fail 体检报告 |
| 0.5 定大字 | `python scripts/talk.py talk.json --headlines heads.json` | 每镜屏幕大字（必须是 `line` 的逐字开头） |
| 1. 给视频取页 | `python scripts/videopage.py <页面目录> <视频页目录>` | 同一份 HTML，藏掉 h1/导语/图注/页脚，截出**图形区**（749×217 这种宽条） |
| 2. 推每镜怎么拍 | `python scripts/shot_plan.py plan.json shotplan.json --headlines heads.json` | 每镜 `layout / beat / frames / why / alt`，附 0-fail 断言结果 |
| 3. 出帧 | `python scripts/compose_layouts.py <视频页目录> <帧输出目录> shotplan.json [--only A,B] [--no-head]` | 1920×1080 整帧；宽条页走 S1~S12，整页走 A~L；标了 `frames:2` 的镜多出一张 `<页名>b.png`（推近）；`--no-head` 出无字帧（见「一·补二」） |
| 4. 拼渲染脚本 | `python scripts/build_script.py <帧目录> <alignment.json> out.script.json --lines talk.json [--estimate] --media-prefix …` | 渲染引擎要的 `script.json`：`line` 作字幕与配音，时长抄配音对齐（配音前用 `--estimate` 估） |
| 5. 成片 | `node <repo>/video/make.mjs out.script.json` | `output/<日期>/抖音/.../video.mp4`（不给 `--skip-voice` 就顺手配音） |

第 5 步复用 `video/` 抽屉（HyperFrames 0.9.41 + 本地 VoxCPM 配音 + Whisper 对齐），`make.mjs` 一条命令走完：校验→配音→合成→混音→渲染。**画幅不写死**：`build_script.py` 从帧的实际尺寸写出 `size:{w,h}`，`make.mjs` 透传 `--w/--h`，横页出 16:9、竖页出 9:16。

## 一·零、顺序不可颠倒：稿子 → 匹配 → 出片

**画面是为口播稿服务的，所以稿子必须先单独过审。** 一发现问题就直接往下渲，出来的必然是"按我的思路做完，却不是你要的效果"，而且耗时最长、返工最贵。

| 阶段 | 出什么 | 出口条件 |
|---|---|---|
| ① 口播稿 | 只有文字（`talk.json`）＋`vo_check.py` 报告 | 人读完点头；机器 0 fail |
| ② 画面匹配 | 每句配哪一页、大字取哪几个字、要不要推近（一张表） | 人看完这张表点头 |
| ③ 出片 | `videopage → shot_plan → compose → build_script → make` | 上两阶段都过了才跑 |

`vo_check.py` 查的是稿子层能机器判的部分：第一句必须出现主角名（不许拿"他"开场）、单句 12–38 字、每句开头要咬住上一句、数字口径必须回原文、时长估算。判不了的（讲没讲清楚、情绪对不对）会以 `NOTE` 列出来给人看——**NOTE 不是通过，是要人确认一次**。

**去 AI 味交给 `skills/lieflat-less-ai-tone`，本 skill 不自建词表。** 稿子 ≥500 汉字时跑 `detect.py <稿.txt> --json` 出分级报告；60–90 秒的短稿（300–400 字）到不了它的检测门槛，就按它那 13 条规则人工过一遍、列候选给人点头，**报告出来不等于可以自己改**，按那边的「报告→等回复→改写→复测」走。

写法与去 AI 味的完整清单在 `references/voiceover.md`。

## 一·补、一屏只能有一套大字（2026-11-16 实拍踩到）

第一版直接把图解页整页塞进画面，再在旁边叠一句提炼大字，口播又是第三套说法。**一屏三套字**：
页首自己的 h1「锁住、隔开、稳住」、叠上去的「信托一次办三件事」、以及两者都不是的口播原句。
观众听的、看的、图上写着的不是同一件事，看下来必然云里雾里。

两条硬规矩，都是为了把三套字压成一套：

1. **视频素材取图形区，不取整页**（`videopage.py`）。页是给人读的，h1 本身就是它的大字；视频的大字由我们写，页就别再带一个。
2. **屏幕大字 = 这一镜口播的第一个分句，逐字相同**（`talk.py` 断言）。听完一句，看到的就是这句的开头，不需要观众自己做对齐。

页只留图形区之后，素材形状变成宽条（宽高比 1.9~4.3）。A~L 那十二套是给 1080×800 整页排的，宽条塞进"左页右文"会缩成一条看不清的细线——所以按形状再立一族，`S1`~`S12`（名目见 `references/layouts.md`）：上图下文 / 上文下图 / 题签左 / 题签右 / 出血压顶 / 缩图巨字 / 双块并置 / 顶出血压线 / 斜置 / 开窗 / 刻度线 / 巨号垫底。**版面先服从素材形状，再服从句子。**

## 一·补二、无字模式：屏上不写字，文字交给字幕条（2026-11-16 改口径）

`compose_layouts.py --no-head`。默认关（`NO_HEAD = False`），不加这个开关就是一·补那套「屏幕大字 = 口播首分句」。

为什么要有这一档，是量出来的：一镜一刀，屏幕大字只装得下一句 16 字以内；而口播在同一镜里讲 20–37 字、3–5 个信息点。念到第二个点以后画面上没有任何东西在跟，听感就成了「口播已经说到下一页，画面还停在上页」。要么把一镜切成三刀（成本翻倍），要么把文字交给渲染层的字幕条、画面专心做图。

三条实现约定，改的时候别破：

1. **底部留 0.15H 给字幕带**（`SCR = round(H * 0.15)`），图底边贴这条带的上沿（`head_y()`），不是画布垂直居中。居中会让图飘在半空、图与字幕之间空出 200px，观众视线要跳一层。
2. **镜号和装饰线一律挂到图上方**。图贴底之后，图下方就是字幕带，任何东西压进去都会被字幕盖住。
3. **出血上限从 1.04 收到 0.96**（`strip_fit` 的 `max_bleed` 默认值随模式变）。视频页的图形区几乎是贴边的（藏掉了 h1/导语），1.04 加上运镜再推 4–6% 就会切字——实测 01-event 的「1993」「辞去…全部职务」两处都被裁掉。0.96 × 运镜 1.025 ≈ 0.984，仍在画布内。

代价：宽条页受 `max_bleed` 限宽，图高最多到 0.536H（比例 3.45 的页），所以「无字之后把图放大」对宽条页无效。十二套之间的区别只能靠位置、裁切、倾斜、双块、装饰线来撑，不能再靠字的排法。

**已知缺口**：无字分支只写在 `S1`~`S12`，`A`~`L` 这十二套整页版式还没改。一支片里如果 shot plan 同时给了 A~L 和 S 族，会出现一屏有字、一屏没字的混排——要么整片都用 S 族（宽条素材下的默认行为），要么等 A~L 补齐再混用。

## 二、版式由文章推，不由人选

这一步的输入全是 plan 里已经有的东西：

- `claim`（这张图证明哪句话）→ 句子长短、有没有「不是…而是…」、有没有两个数字
- `reads_as`（读者该看见什么）→ 写了「细节 / 局部 / 一角」就该开窗放大
- `figure_type`（这镜是什么形状）→ 是结构、过程、对比，还是给数

**先判 beat（这镜在干什么）**：首镜=起手、末镜=收束；claim 里有「不是/而是/对上/旁边」=对比；结构类图型（unit-grid / kanban / layers / nested / venn / steps / loop / quadrant / tree / pyramid）=拆解；过程类（waterfall / timeline / sankey / journey / gantt）=过程；两个以上数字、或柱/差值/哑铃=给数；其余=叙述。

**再按 beat 取候选**：起手→C/B/A，叙述→A/B/D，过程→D/E/B，对比→I/J/B，拆解→G/H/E/J，给数→A/H/I/B，收束→L/I/K。两个修正：`reads_as` 有细节词 → 开窗 H 提前；句子 >18 字 → 剔竖排单列，≤12 字 → 剔双列并优先 C。

**最后过全局约束**（这些是 FAIL，不是「看着顺眼」）：

| 约束 | 为什么 |
|---|---|
| 相邻两镜不同版 | 连着两镜一个手法，第三镜观众就走了 |
| 首镜不许切页/开窗/出血/压边 | 开场得先把整页立住，否则第一秒看不懂这是什么 |
| 末镜压边（撞了改出血） | 收束要「翻过去」的手感 |
| 长句不许进竖排单列；短句用双列只算 WARN | 竖排吃字，一句 22 字会顶出画面 |
| 全片至少一套竖排、一套重手法 | 横排铺到底，画面没有呼吸 |
| 8 镜以上要有一次巨号编号 | 中段给观众一次节奏点 |
| ≤12 镜时一套版只用一次 | 库里有 12 套，够轮；重复是懒 |
| 每镜必须写 `why` | 说不出它服务哪句话，就别用这套 |

### 一页两拍（`frames`）

一页一镜是底线。信息密的页给两拍：**第一拍全景，第二拍推近**（`compose_layouts.py` 按画面重心裁 1/1.26 再放回原尺寸，音频仍是同一段、时长对半分，不用重配）。

什么时候拆，也由 plan 里的话决定：

- `reads_as` 写了「细节 / 局部 / 一角」且是拆解类 → 这页有个点值得再看一眼；
- 拆解类 claim 超过 18 字、过程类超过 22 字 → 一页要装两层意思，一拍讲不完。

首镜、末镜永不拆（开场要一次立住整页，收束要一次到位）；10 镜最多 2 处拆拍——全是推近，就不叫推近了。这两条都是 FAIL，不是建议。

同一篇文章，机器排出来的顺序和人手排的会不一样，这是好事——**这一步的价值就是不用人再做一遍审美决策**。

## 三、十二套版面（`compose_layouts.py`）

画的不是「文字放哪」，是**页与字的图文关系**：字压页、页遮字、页开窗、竖线分栏、巨号垫底、字出血。全表与踩坑见 `references/layouts.md`。

| 版 | 手法 | 一句话 |
|---|---|---|
| A / B | 页左·字右横排 / 页右·字左横排 | 最稳，底色用 |
| C / D | 页左·竖排单列 / 页右·竖排单列 | 批注口吻，短句 |
| E | 页左·竖排双列 | 长句也能竖 |
| F | 批注式：页铺满，小字竖排在页外 | 页自己就是主角 |
| G | 字块切页：字压页右侧留白，纸色底衬只压 58px | 图文咬合 |
| H | 开窗放大：右下开一块「局部放大」，裁右下 52%×48% | 用放大代替重讲 |
| I | 字出血：92px 巨字贴边 | 全片结论句 |
| J | 竖线分栏：一条线切开，字在左竖排 | 转折 |
| K | 巨号编号垫底（190px `06`） | 只调节奏 |
| L | 出血压边：页右侧出画 62px | 收尾 |

编排器 `PREFER` 按字数分 band 选版并避开最近两镜；也可以像样例那样在 `--headlines` 里显式给 `layout`，显式优先。

## 四、屏幕大字谁写

**由 AI 从 `claim` 重写，不是手写项。** `scripts/conclusions.py` 只是没人盯时的机械兜底：砍时间前缀 → 在标点边界取最长窗口 → 砍两三个字的悬空拖尾（`--max 26`）。机器压出来的句子会断半句（「执掌 33 年的 CEO 把总裁」），所以有 AI 在场时必须自己重写。

## 五、硬规矩（构图、诚实）

**构图**

- 页与字**不许互相遮挡正文**：纸色底衬只压页面右侧留白那 58px；出血压边只在 62px 以内；开窗裁的是页面局部，不许把整页缩小再放一遍（那是「复制两遍」，不是放大）。
- 页面缩放全片用**同一个系数**，否则每镜字大小跳动，像不同的片子拼起来。
- 大字基线至少距画面边 40px；竖排字列间距 ≥ 相邻两列字宽。
- 一镜只说一句话。一句讲不完就先拆镜，不是缩字号。

**诚实**

- 屏幕大字必须能落回 `claim`；`claim` 又必须能落回原文（`article-figures` 的 `plan_check.py` 已经查过 `anchor_quote`）。
- 数字、金额、时长不得在构图层新增；构图层只搬字，不造事实。

## 七、依赖与已知限制

- **Python**：`pillow` 足够，不需要浏览器。
- **字体**：屏幕大字用汇文明朝体（`.otf`）。不写死路径：`ARTICLE_VIDEO_FONT` 指文件，或 `FIGKIT_FONTS` 指字体根目录（与 `article-figures` 共用）。找不到会明确报错，不会静默换字。
- **渲染**：需要 `video/` 抽屉（Node + HyperFrames + 本地 VoxCPM）。没配音时加 `--skip-voice` 复用已有 `narration.wav` / `alignment.json`。
- **已知限制（都在代码里留了印记，不是"以后再说"）**：
  - 推近帧按**整帧裁**，不是按某个元素推；图上要精确推某根柱，得在 shot plan 里手写 `focus:{x,y}`（字段还没实现）。
  - `build_script.py` 要求帧数与配音镜数一致：改镜数就得重配音，这是引擎侧的约束。
  - 竖版（1080×1920）要改 `compose_layouts.py` 头部的 `W/H` 常量，还没做成 `--size` 参数。
  - `K` 的巨号按镜次奇偶换角（左上 / 右下），只支持这两个角。
  - **`make.mjs` 会误判没有 VoxCPM**：本机首次加载 VoxCPM 实测 233s，而探测窗口 60s，`make.mjs` 直接报"没有可用的配音方式（要求 voxcpm）"。绕法：先单独跑
    `node video/step2-voice/voice.mjs <script.json> --backend voxcpm --voice news-man`，成功后再 `make.mjs --skip-voice` 复用 `narration.wav` / `alignment.json`。
  - **字幕条是二选一的口径**：默认不带逐字字幕条——屏幕大字自己就是那一句（口播的首个分句），再加一条字幕会和它重复；走 `--no-head` 时反过来，屏上不写字、字幕条由渲染层画。两种不能混着用，理由与代价见「一·补二」。
  - **`--no-head` 只覆盖 `S1`~`S12`**，`A`~`L` 仍是带字版；混排会一屏有字一屏没字。

## 八、与其它 skill 的分工

| 要什么 | 走哪 |
|---|---|
| 文章 → 图解页 PNG | `article-figures`（本 skill 的素材来源） |
| 图解页 → 16:9 / 9:16 图解短片 | **本 skill** |
| 平台比例卡片 → 竖屏卡片动画 | `card-video` |
| 分镜式讲解片（自己搭镜头） | `explainer-video` |

顺序：`article-fetch` → `article-rewrite`（可选）→ `article-figures` → **`article-video`**。
两条线只共享输入文章：出图那边不必为视频改布局，出片这边也不必复用出图的那套排法。
