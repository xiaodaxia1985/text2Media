# Article Video · 文章转图解短视频

> **开工之前先读项目根的 `AGENTS.md`**：那是硬规矩（先出方案等批、不许自造、卡住怎么办、已确认的坑、沟通规矩）。
> 本 skill 只管怎么干活，`AGENTS.md` 管什么不许干。两者冲突时以 `AGENTS.md` 为准。

**喊它什么**：图解短视频 / 文章转视频。一句话记：**先把话说顺（口播稿）→ 再为一句话画一张图（骨架，一镜一组件）→ 配音 → 静帧过审 → 才渲成片。**

**底座是 `tools/anything2explainer`（a2e）的「一镜一组件」模式**：版式就是那一镜的 `.tsx` 文件，`import` 进 Main 就必然出现在画面里。所以「骨架定了却没进画面」这件事，从结构上不可能再发生。**不许再走卡池套 props 那条路**（talkcraft 108 卡已于 2026-11-18 整体弃用：内容是变的、卡是死的，必然「内容迁就卡」）。

一支片就三件事：**每镜讲哪句、这句的画面关系是什么、第一眼主体是谁**。三件都不该临时拍脑袋：镜次来自文章结构，画面关系来自这一镜在干什么（`references/shot-design.md` §2 的 22 条关系），屏幕大字逐字取台词开头。

**开工先看 `references/pipeline-checklist.md`**：那是「用户说要用这套 skill 出一支片」时的逐条待办（**P1–P9**，每步只写输入、调用、出口条件）。第 0 条铁律写在最前面：**遇到问题先查官方文档 / GitHub / 社区，不许自造轮子；不确定就停，不许闷头跑到错。** 三个必须停下来等人的点：**口播稿、骨架联系表、静帧批**。

**出片命令统一走 `tools\t2m-video\`**：`render.ps1`（一步出片）、`still.ps1`（单帧）、`sheet.ps1`（联系表）、`mix_bgm.ps1`（垫乐混音）、`clean.ps1`（清临时文件）。临时目录已钉在 `项目根\.tmp\rt`，**禁止落 C 盘**；出片确认后必须跑一次 `clean.ps1`。用法见该目录 `README.md`。

**片头 / 片尾 / 页脚 / 垫乐**：竖版定版规则见 `references/brand-bookends.md`（2026-11-19 拍定）。四条记死：只用自有圆环台阶标记、不放人物照片；片头卡框与圆环先立住再让台阶一级一级升起；页脚不放页码与总页数；垫乐 -13 dB 混入且**混后 LUFS 必须与无乐版一致**。

## 一·零·零、触发即按待办清单执行（2026-11-17 定）

本 skill 一被触发（「用这套 skill 出视频」「这篇文章出个视频」「按老套路出片」「文章转视频」），**第一动作不是写稿，是读 `references/pipeline-checklist.md` 并按 P1–P9 推进**：

1. **建待办**：`task_create` 把 P1–P9 建成本次任务清单；每段开始 `in_progress`、走完 `completed`，不许跳段。清单全程挂在会话，中途被打断也不撤。
2. **三个审批点必须弹窗**：**P2 口播稿 / P3 骨架联系表 / P6 静帧批**（匹配表只做出图依据，不单独审批——纯文字表看不出排版问题，图才是判据）。到点调用 `interaction_ask` 弹审批卡，选项固定 `通过` / `退回修改` / `暂停`。**用户选「通过」才进下一段**，不许只在正文里问「你看行吗」。
3. **审批留痕**：每次结论回填 checklist 末尾的「审批台账」（时间 / 阶段 / 结论 / 修改项 / 批次）。
4. **卡住先查**：任何报错或效果不对，先按第 0 条查官方文档 / GitHub / 社区；要自建脚本或新版式，先报批。
5. **反馈节奏**：单步预计 >10 分钟先报预估；实际跑 >30 分钟无结果，停下报「卡在哪、还剩多少、要不要换法」，由用户决策，不许闷着跑。

四条不许破：**稿子没过审不配画面；骨架没过审不配音；静帧没过审不渲整片；报错不许写补丁脚本绕过。**

> **冲突裁决**：本文件其余章节是背景资料（含 2026-11 上旬的 step4-motion / talkcraft 经验）。**执行时只有 `references/pipeline-checklist.md` 说了算**；两者矛盾，以清单为准。

## 一·零·一、渲染与包装分离（硬契约）

**画面归 talkcraft，声音/字幕/壳归我们。** 别把它的卡搬进我们工程（搬一次改一次，改完就是自建版式），而是把稿子送进它的管线，取回一个**无声画面母版**，我们接声字壳。

- 给它四样：`timestamps.json` / `semantics.json` / `SHOTBOOK.md` / `shots.json`（末镜 `end` = 配音秒数），外加 **`durationInFrames` 钉死 = round(配音秒数 × fps)**，禁止它估时长。
- 它产出：`node <talkcraft>/scripts/render_shots.mjs --shots shots.json --concat out/assembled.mp4`，**只取 `--concat`，不许 `--mux`**。
- 我们接入：整条 `narration.wav` + 从 `alignment.json` 生成 ASS 烧字 + 片头尾/品牌条/转封装，一条 ffmpeg 合成。
- 时间轴唯一真相 = `alignment.json`（归一后）；`shots.json` / `durationInFrames` / `subs.ass` 全部从它派生。

全部命令、判据、五条红线见 [`references/talkcraft-handoff.md`](references/talkcraft-handoff.md)。**这一步不是"可选优化"，是唯一允许的出片路径。**

第五条（2026-11-18 加，与前四条同级）：**画面版式只能从 `tools/video-talkcraft/template/cards/` 的成品组件里逐镜选型，不许自建 `atoms` / `families` / 新族。** 改个文件名再自建等于违规——本项目已因此被推翻两版（36 镜 `families.tsx`、47 镜 `atoms.tsx`）。选型表见 `references/pipeline-checklist.md` 阶段 3.6，工程侧自检见 4.0a。

**配音另有一条硬规则（2026-11-18 用户定）**：长句必须切成短句再配，单段 ≤ 22 字，逐段生成再拼回整句（`voxcpm_batch.py` 已内置 `split_long()`）。长句在 6 GB 卡上会把显存顶满、单条从 60 秒塌到 20 分钟且不出段。详见 [`references/voice-splitting.md`](references/voice-splitting.md)。

## 一、五步

| 步 | 命令 | 产物 |
|---|---|---|
| 0. 写口播稿（**最重要，稿子不过不许往下走**） | 按 `references/voiceover.md` 的「正文通则十条」写 → `python scripts/vo_check.py talk.json --subject <主角名> --article <原文.md>` → `python ../lieflat-less-ai-tone/scripts/detect.py <稿.txt> --min-chars 0 --json` 去 AI 味并复测 | `talk.json`（每镜 `id / headline / line`）＋ 0-fail 体检 + detect 前后对比（A/B 清零） |
| 0.5 定大字 | `python scripts/talk.py talk.json --headlines heads.json` | 每镜屏幕大字（必须是 `line` 的逐字开头） |
| 1. 给视频取页 | `python scripts/videopage.py <页面目录> <视频页目录>` | 同一份 HTML，藏掉 h1/导语/图注/页脚，截出**图形区**（749×217 这种宽条） |
| 2. 推每镜怎么拍 | `python scripts/shot_plan.py plan.json shotplan.json --headlines heads.json` | 每镜 `layout / beat / frames / why / alt`，附 0-fail 断言结果 |
| 3. 出帧 | `python scripts/compose_layouts.py <视频页目录> <帧输出目录> shotplan.json [--only A,B] [--no-head]` | 1920×1080 整帧；宽条页走 S1~S12，整页走 A~L；标了 `frames:2` 的镜多出一张 `<页名>b.png`（推近）；`--no-head` 出无字帧（见「一·补二」） |
| 4. 拼渲染脚本 | `python scripts/build_script.py <帧目录> <alignment.json> out.script.json --lines talk.json [--estimate] --media-prefix …` | 渲染引擎要的 `script.json`：`line` 作字幕与配音，时长抄配音对齐（配音前用 `--estimate` 估） |
| 5. 成片 | `remotion render src/index.ts <Id> "out\seq-<Id>" --sequence` 逐镜出 PNG 序列；`python video\step4-motion\join_full.py --audio` 拼整片 | `output/<日期>/抖音/.../整片_*.mp4`（片头 + 16 镜 + 片尾，音频按同一条时间轴拼） |

第 5 步复用 `video/` 抽屉（HyperFrames 0.9.41 + 本地 VoxCPM 配音 + Whisper 对齐），`make.mjs` 一条命令走完：校验→配音→合成→混音→渲染。**画幅不写死**：`build_script.py` 从帧的实际尺寸写出 `size:{w,h}`，`make.mjs` 透传 `--w/--h`，横页出 16:9、竖页出 9:16。

## 一·零·二、构图两条硬原则（2026-11-18 定，源自 anything2explainer / video-talkcraft）

这轮长片改到第 4 版仍"看起来像同一张表"，根因不在族不够多，在**两件事没定**：

1. **一镜一设计**：版式从「这一镜要说的话」长出来，**不从族库里挑**。族只提供画法语法（线、块、字、环、轴），位置/尺寸/叙事角色由这一镜的关系决定。看 `references/shot-design.md` §1 的三步（关系 → 第一眼主体 → 配角降级）与 §2 的 22 条关系表。
2. **一致性来自 token，不来自版式重复**：色板、字阶、栅格、字幕带、动效曲线固定；**布局必须变**。一致性放外框，内部才敢放开。

配套几何规范在 `references/composition.md`：12 栏栅格（栏宽 107.33）、间距令牌 8–160、六档字阶、**定妆帧九项**。出图前定死，出图后量。

**两道闸门，缺一不可**：
- `scripts/rhythm_check.py` 管整片节奏（方向/体量/连续性配额）
- `scripts/frame_max_object.py` 管单帧主体（≥110px、不贴边、不进字幕带、居中偏差 ≤48）

## 一·零、顺序不可颠倒：稿子 → 匹配 → 出片

**画面是为口播稿服务的，所以稿子必须先单独过审。** 一发现问题就直接往下渲，出来的必然是"按我的思路做完，却不是你要的效果"，而且耗时最长、返工最贵。

| 阶段 | 出什么 | 出口条件 |
|---|---|---|
| ① 口播稿 | 只有文字（`talk.json`）＋`vo_check.py` 报告 ＋ `detect.py` 前后对比 | 人读完点头；机器 0 fail；去 AI 味复测 A/B 清零 |
| ② 画面匹配 | 每句配哪一页、大字取哪几个字、要不要推近（一张表） | 人看完这张表点头 |
| ③ 出片 | `videopage → shot_plan → compose → build_script → make` | 上两阶段都过了才跑 |

`vo_check.py` 查的是稿子层能机器判的部分：第一句必须出现主角名（不许拿「他」开场）、单句 6–38 字、每句开头要咬住上一句、数字口径必须回原文、时长估算。时长按 4.2 字/秒 + 0.35s/句 估：**≤90s 通过，90–120s 只报 WARN**（语速可调 1.2／1.5 倍，按实际渲染定，不许为凑时长砍句），超过 120s 才 FAIL。判不了的（讲没讲清楚、情绪对不对、首词是不是语义回指）会以 `NOTE` 列出来给人看——**NOTE 不是通过，是要人确认一次**。

**去 AI 味交给 `skills/lieflat-less-ai-tone`，本 skill 不自建词表。** 短稿也能跑，但**必须加 `--min-chars 0`**：

```powershell
python skills/lieflat-less-ai-tone/scripts/detect.py <稿.txt> --min-chars 0 --json > before.json
```

不加这个参数，脚本会以「汉字 <500，检测无意义」直接拒跑（60–95 秒的口播稿只有 350–450 字，永远进不去）。跑完照它那套走：改前报告 → 按白名单改 → 复测出前后对比。本产线上「等用户回复」这一环取消，但**判不了的（比喻贴切度、暗喻、案例凑数）仍然不判不改，只列人审**。

两条实测口径：`detect.py` **抓不到「不是 A 是 B」的翻案腔**（规则 1 必须手查）；C 级的句长 CV、两句／三句同构默认保留——硬推参差比不改更糟。

写法与去 AI 味的完整清单在 `references/voiceover.md`。

## 一·零补、开篇先给主题和结论（2026-11-16 用户改稿后定）

**开场不是推理番，观众不会等你铺垫到第 10 秒。** 之前 01 只给半句（「最缺的不再是把东西做出来」）、结论压到第 3 镜（第 11 秒）的写法已经被否，改法固定成三镜：

| 镜 | 干的事 |
|---|---|
| 01 | 主题＋结论并进一句，最好逐字取原文标题的判断 |
| 02 | 先一个 6–12 字短句交代为什么不是别的答案，再给证据 |
| 03 | 给一句立场或转折，**不许复述 01 的结论** |

整片骨架：**片头（账号介绍 ≤5 秒）→ 01 主题＋结论 → 02 为什么 → 03 判断 → 正文取证 → 片尾（CTA 2 秒）**。结论必须落在开场 15 秒内；片头不放在结论前面，否则钩子被 5 秒账号介绍打断。

**片头、片尾这类新增段落，先把文字稿交人确认，确认前不写组件、不配音、不渲染。** 文字没定就开做，做几轮都是白做。
反例、四条硬规矩与「为什么标题可以直接当 01」见 `references/voiceover.md` 的「二·补」；**正文怎么往下推（结构七条／语言三条）见同一份的「二·补二」**——那十条是跨体裁的，别把某篇文章的主题当规则。

## 一·零补二、出片这一段用 Remotion 做元素级动画（2026-11-16 定型）

**一镜一族，族里每个元素自己进场**：线长出来、点弹进来、条涨上去、卡推开、字遮罩升起、光束扫过去。页与页之间不做转场，靠上一镜的最后一个动作接下一镜的第一个动作。

这一条是被否出来的：每镜一张整页图、页间淡入淡出或硬切，用户的原话是「进入和出去都很跳跃」「页面老是跳来跳去」「不就是在放 pdf 吗」「弱智的很」。长页滚动版同样被否。

引擎三条路都试过，只这条通：HyperFrames 的整页思路已废；Revideo 0.11.0 在 Chrome 157 上渲染必崩；Motion Canvas 3.17.2 没有 headless CLI。**Remotion 4.0 可用，CLI 能 headless 出 PNG 序列。**

三条不能破：

1. **每镜帧数由配音实长决定**——`帧数_i = (start_{i+1} − start_i) × fps`，末镜到总长；段间静默里画面留上一句最后一帧，不提前切页。配音对齐要先按 wav 实长归一（VoxCPM 写完全局加过速，原时间戳末镜会超出总长）。
2. **组件里的时点写秒，不写帧**——稿子一改、时长一变，全部要重排。这是已知代价，不是 bug。
3. **每个组件渲完抽末帧看一次**——色阶反了、数字压字、三层互压，光读代码看不出来。

16 族怎么落成代码、时点怎么排、整片怎么拼、六个工具坑，全在 `references/remotion.md`。

## 一·零补三、解说词怎么变成画面：三条判据（2026-11-16 补）

族选错了，动画做得再细也是错的。**判据不在「这句有没有数字、有没有两个对象」，在那句真正在说什么。**

### 判据 1：先判这句是过程还是状态

| 句子在说 | 语法方向 | 该用的手法 |
|---|---|---|
| 一个主张被推翻、被驳回 | 过程：立起 → 划过去 → 沉下去 → 让位 | 划线穿越整句 + 主张沉降 |
| 从 A 走到 B，路上做几件事 | 过程：迁移 | 一个出发 + 一条路径 + 路中节点 + 一个抵达 |
| 同一批人分成两拨 | 状态：分布 | 点阵、条形 |
| 两边之间夹着一条窄缝 | 状态：三段 | 比例带，中间段最宽，数字落在中间段 |
| 判据缺失、判不了 | 状态：悬置 | 空框、章落不下来、问号域 |

**把过程拍成状态，是最常见的一类错。** 句子在讲「主张被驳回」，画面把主张和结论上下并排——观众看到两句陈述，看不到一次驳回。反过来，句子在讲「判不出来」，画面盖了一个已落定的章，方向正好相反。

### 判据 2：重心词要占最大面积、或最后落下

每句有一个重心词。判断方法：**删到只剩一个词，哪个词删了这句就不成立**，它就是重心。

数字最容易挂错地方。句子说「大多数人都烦中间那个状态」，画面把百分比挂在「某个类别」那一侧，读下来变成「这个类别占大多数」——数字是对的，意思反了。

### 判据 3：陪衬不能和主角等重

一句里通常有一个主角、一个陪衬。陪衬必须明显轻：面积更小、颜色更弱、位置更靠边，三条至少做到两条。陪衬做得和主角一样大，观众读成「两者并列」，而句子说的是「其中一个是重点」。

### 匹配表每镜写满四格

缺一格就是没想清楚，别往下渲：

| 格 | 写什么 |
|---|---|
| 重心词 | 这句删到只剩一个词，是哪个 |
| 语法方向 | 过程 / 状态 |
| 承载元素 | 画面上哪个元素承载它，写成看得见的东西（「中间带」「落不下来的章」） |
| 陪衬 | 谁是陪衬，用什么手法做轻 |

**族的语法方向和句子相反时，改法不是「加大这一镜的动画强度」，是换族。** 反例都长这样：族没错、动画也没错，方向拧了——加大强度只会让错得更响。

## 一·零补四、片头片尾是固定资产（2026-11-16 定版，90/100 那一版）

## 一·零补五、字幕跟着分句递进（2026-11-17 落地）

**原来是「整镜一句常驻」**：一镜 4~7 秒里那句话 20~40 字，从第一帧挂到最后一帧。口播念到第二、第三个分句时，屏幕上还是整句，观众没有「念到哪儿」的参照。

现在改成**按分句换页**：念完一个逗号才换下一页，一页 6~12 字。

三条实现约定：

1. **分页交给官方，不自己写算法。** `@remotion/captions` 的 `createTikTokStyleCaptions()` 把逐字 token 收成「页」，页边界由 token 上的 `pageBreakAfter` 决定。数据里在标点（`，。？！；：、…`）那枚 token 打 `pageBreakAfter: true`，再把 `combineTokensWithinMilliseconds` 给一个很大的值，页就严格按分句断。**不要**反过来把毫秒窗口调小去凑「一页几个字」——那是按固定毫秒切，会把一句话从中间劈开。
2. **数据来自 `alignment.json` 的逐字 `chars`，不用重新转写。** 生成器 `scripts/make_caption_track.py` 把每镜的逐字时间戳切成 `{镜 ID: Caption[]}`，时间折算成镜内相对毫秒：`relMs = (charStart − 前面所有镜的帧数/fps) * 1000`。**别拿 `scene.start` 当镜起点**——各镜开头有 0.01~0.05 秒空气，用 scene.start 会让字幕整体晚于画面。
3. **一镜一组字幕，不做全片浮层。** 官方 `remotion-captions/display-captions.md` 的原话是「不要把多镜字幕合成一个覆盖全片的浮层」：浮层在挪镜、裁剪、变速时字幕不跟着走。所以字幕带挂在每个 `<Series.Sequence>` 内部，吃本镜的那一份数据。

配套两件：

- **深底镜的字幕要浅色**：颜色不再由各镜自己决定，改由整片的镜头表统一管——给那面镜写 `captionColor`（16 镜里只有第 10 镜是深底）。
- **最后一页不随配音结束消失**：13~15 镜是 1.5~1.7 秒配音配 2.2~2.5 秒画面，镜尾有 0.6~0.8 秒空气；字幕跟着声音一起消失会让底部空一块，所以最后一页留到本镜切走。

**分页机制用官方、皮肤自己写。** 官方 `Basic Captions` 元素是 TikTok 皮肤（64px 白字 + 深灰药丸底 + Arial），压在浅纸底上会跳出来；它已原样存在 `step4-motion/src/basic-captions.element.tsx`，要换回官方皮肤就替换组件，机制完全相同。

改字幕前先把整片里的常驻字幕摘掉——**一屏两套字**是这条产线踩过最多次的坑（见「一·补」）。

## 一·零补六、版式先查官方，不自己发明（2026-11-17 定）

### 元原则

**任何一个「这里该怎么排」的问题，先查官方文档 / 官方示例 / 社区组件库，再动手。** 用户原话：

> 遇到问题先看官方文档或者里例子或者社区。肯定有人比我们先遇到过。

后半句是重点：**"有人比我们先遇到过"就意味着答案已经存在，自己发明出来的那套只能算猜测。** 这条排在所有具体规则之前——具体规则会过时，这条不会。

反例都长这样：遇到「文字为什么只在左半边」，前四版在调对齐、调边距、调字号阶梯，调了四轮；去查官方 layout-utils，根因是**字号写死**（`宽度 = 字数 × 字号`），一行 `fitTextOnNLines()` 就解决了。

### 这一轮的根因：字号不是「调」出来的，是「反推」出来的

中文 6 个字写 372px，实际占 372，内容宽 1640 —— 永远只占左边 23%。调多大都是猜。

官方 `@remotion/layout-utils` 的 `fitTextOnNLines({text, maxBoxWidth, maxLines, fontFamily, fontWeight, maxFontSize})` 用**容器宽度反推字号**，中文同样成立（**中文字宽 ≈ 字号**，所以 `1640 / 字数` 就是铺满的字号）。

三条硬约束（缺一条就量错）：

1. **字体先加载完再测量。** 否则量的是 fallback 字体，反推出来的字号是错的 → 所以 `fitBox()` **必须写在组件内部**，不能放模块顶层。
2. **测量与渲染用同一套 font 属性**：`fontFamily / fontWeight / letterSpacing` 三样一致，否则量 205px、渲出来撑破。
3. **边框用 `outline`，不用 `border`。** Remotion 默认 `box-sizing: border-box`，`border` 会吃容器宽度，量出来的宽度和渲染出来的宽度差一个边框。

### 共享骨架（16 镜共用，`video/step4-motion/src/layout-kit.tsx`）

| 导出 | 作用 |
|---|---|
| `BOX = 1640` / `PAD = 140` | 1920 宽、左右各 140 的内容区 |
| `fitBox(text, weight, maxFontSize, maxLines)` | 反推铺满 1640 的字号（**调用点必须在组件内**） |
| `Chip` | 顶部居中描边 chip，位移进场 |
| `Rule` | 横贯线，`anchor='center'` 从中间向两端拉开 |
| `Foot` | 中轴收底注 24px |
| `Line` | 中轴一层字，含 fontSize / top / clipPath / translate 套路 |

### 版式六条（每镜至少做到四条，做不到要在匹配表里写明为什么）

1. **一层撑满内容宽度的字**：用 `fitBox` 反推，不写死。
2. **一条横贯 1640 的线**：全屏唯一的越界元素。
3. **重心走垂直中轴**，不靠左。上一版 16 镜里 15 镜重心落在左半、右侧 1086px 全空，密度差 35 倍 —— 这不是风格问题，是没排。
4. **字号阶梯 ≥ 3 倍**：最小 22–26px，最大 150–380px。中间层 70–120px。
5. 边框用 `outline`；chip 进场用位移不用 `clipPath`（`clipPath` 会把描边切掉一条）。
6. 收底一条 24px 中轴注。

### 内容类型怎么选版式（定义权归官方与社区，不归自己）

| 内容类型 | 版式语法 | 出处 |
|---|---|---|
| 数据型（量级落差大） | **等距刻度**：量级由档位数承担，不由条长承担 | 本轮定版（第 2 镜） |
| 数据型（同量级对比） | 共用一把尺的条 | video-shotcraft `comparison-bars` |
| 时间型 | 相机沿轴跑，**动的是镜头不是元素** | video-shotcraft `timeline-travel` |
| 过程（主张被驳回） | 立起 → 划过去 → 沉下去 → 让位 | 一·零补三 判据 1 |
| 过程（迁移） | 一个出发 + 一条路径 + 路中节点 + 一个抵达 | 同上 |
| 状态（分布） | 三段比例带 / 等距刻度 | 同上 |
| 悬置（判不了） | 空框 + 章落不下来 | 同上 |

两条硬纠正：

- **条形图各自归一是错的。** 「所有行共用一把尺，绝不每行各自归一」——`comparison-bars` 原话是 `Scaling each row to itself is what makes a small category look like it beat a large one`。但**共尺也只对同量级成立**：1000:1 的落差用条长表达，末根会小成一根针，这时候换「档位数承担量级」。
- **点阵按行序填色不能表达包含关系**：观众读成两个群体。表达"其中一部分"要用同一根条上的分段。

### 边界（必须向用户讲明）

- `https://www.remotion.dev/templates/` 的免费模板里**没有**信息图、数据、时间轴版式。只有 Blank / Hello World / Next.js / Recorder / Element Library / 3D / Stills / Audiogram / Music Visualization / Skia / Overlay 这类视频包装。
- 配方卡在 `https://www.remotion.dev/docs/resources` 指向的 **`video-shotcraft`**（Apache-2.0，124 张 shot recipe cards，9 类目，索引 `gallery/llms.txt`）。
- 版式原件在 `https://remotionui.com/docs/components`：**装源码进自己 repo，不从 npm 包 import**（`npx remotion-ui@latest add <slug>`）。

### 社区组件是英文，不是不适配

做多语言适配的组件，**容器容纳和布局不随语种变**，英文骨架换成中文照样成立（中文更短，只会更宽松）。因为"是英文"就判不适配，是被明确否过一次的错（原话「你一看到英文就觉得不适配，这就是你最大的问题」）。

## 一·零补七、每镜开头不留空屏（2026-11-17 定，治「跳跃」）

用户连着三次说同一句话：「整个画面的跳跃性还在」「两页之间切换时有黑影」「跳跃性还是在」。前两次都在查转场（淡入淡出、硬切、长页滚动），方向全错。

**根因是每镜开头那半秒到一秒多的白屏。** 16 镜的时序都长成同一个形状：`chip` 0.10–0.55 起手 → 第一个大元素 1.3s 才出来。于是每镜开头 0.5–1.3s 画面上只有一个小 chip 加一条字幕，观众读成"断了，又是一页"。

量法（`remotion.md` 第 12 条的脚本）：成片缩到 320×180 抽全帧，剔掉底部字幕带，四角中位数当背景色，算**与背景差 >12 的像素占比 <1.5%** 的连续区间 —— 那就是观众感知的空屏。

改法（一处也没动转场，只动时序）：

1. `chip` 提到 **0 帧**起（0–0.35 淡入），不要 0.10 才开始。
2. **结构元素**（竖线 / 横贯线 / 三段带 / 双框 / 环 / 纸块）提到 **0.15–0.25s**，0.9s 内画完。结构先于文字出现，画面才有"这一页还在"的延续感。
3. 第一个**主体**（大字、数字、第一张卡）提到 **0.6s 前后**。
4. 尾部的长扫动画（sweep / scan）与收底注不动 —— 提前它们会把节奏压平。

本轮实测：近空白帧 336 → 255（每镜最长空屏 1.33s → 1.00s，多数镜 0.2–0.3s）。**0.2–0.3s 是正常进场，超过 0.5s 才算空。**

铁律：**每镜 0.35s 内必须有 chip，0.9s 内必须有本镜的结构元素。** 做不到就说明这一镜缺一个"承载结构"，不是缺动画。

## 一·零补八、长片不许长得像同一张表（2026-11-17 定，36 镜起用）

**短片的敌人是「单镜不够狠」，长片的敌人是「镜与镜同构」。** 这两套判据别混用：≤12 镜看单镜，≥20 镜看排列。

36 镜那一版被用户一句话判掉：「口播稿长了之后，布局都太一致，水平时间轴出现了很多次。这样是不行」。

四条根因，按这个顺序查：

1. **族 = 版式** → 族一复用就撞脸。族必须 = **骨架类型**（横轴 / 竖轴 / 网格 / 环 / 单点 / 满版，只有这六种真不一样），版式由「骨架 + 方向 + 体量 + 内容」现场生成。
2. **没有第一眼主体** → 官方 `video-layout.md` 的原话是 `Decide what the viewer should notice first in each scene. Build the frame around that one thing.` 1080p 下主标题 **84px**、重要辅文 **44px**；社区判据更狠：图形主体 **≥170px**、大字 **≥96px**，<110px 撑 45 帧就是缺陷。一根线 + 几枚 34px 胶囊撑 100 帧，正是这条说的缺陷。
3. **没有级差** → S 满版重击 / M 中景 / D 细节快切三档，S 档每章 1 个、D 档每章 1–2 个、每 5–6 镜一次全幅变化。
4. **连续性同构** → 连续 3 镜不同方向、连续 2 镜不同族、横轴全片 ≤2、环 ≤2、左右分栏 ≤2（并列栏族全片 ≤1）、同族复用必须换体量或方向。

三条别忘：

- **种类越多越像**，别靠新增族制造差异。「新增竖向导轨族」已被用户当场否掉。
- **一致性放外框**：外框 + 字幕 + 一套动效语法 + 一套色彩统一，布局必须变。sessionmovie 就是这么做的。
- **母题回扣**是长片资产：第 1 章建立的形态在末章以同形态、不同内容回扣，一次就够；重复由此变成结构。

完整配额表、句子关系→骨架查表、机器校验脚本（`frame_max_object.py` 量主体尺寸、`rhythm_check.py` 查配额）与出处，见 `references/long-form-rhythm.md`。**改法优先级固定：先补主体 → 再调配额 → 最后换骨架，反了白改。**

### 补主体时逐族怎么补（2026-11-17 落地，别重新设计族）

第一步「补主体」是**在这一族里把某一样东西放大到能当第一眼**，不是换族。逐族尺度、被降级的配角、以及三处最易压字的位置，见 `long-form-rhythm.md` 的「八·补、每族的『主体补法』清单」。两条硬判据写在这里，别踩第二遍：

1. **只有一个数，别用比例条。** 单条比例条撑不到画面 1/3，剩下全是空；交给巨数字族（D）。比例条至少两根才成立。
2. **回收章不许再用新横轴。** 四个案例/四件事的回扣用 2×2 四格（T 族），横轴全片仍守 ≤2。
3. **2 列分栏可以「末列大块」，≥3 列必须等大。** 并列项被做大，观众会读成「最后一项才是重点」——这是实测抽帧抓到的误读。

## 一·补、一屏只能有一套大字（2026-11-16 实拍踩到）

第一版直接把图解页整页塞进画面，再在旁边叠一句提炼大字，口播又是第三套说法。**一屏三套字**：
页首自己的 h1「锁住、隔开、稳住」、叠上去的「信托一次办三件事」、以及两者都不是的口播原句。
观众听的、看的、图上写着的不是同一件事，看下来必然云里雾里。

两条硬规矩，都是为了把三套字压成一套：

1. **视频素材取图形区，不取整页**（`videopage.py`）。页是给人读的，h1 本身就是它的大字；视频的大字由我们写，页就别再带一个。
2. **屏幕大字 = 这一镜口播的第一个分句，逐字相同**（`talk.py` 断言）。听完一句，看到的就是这句的开头，不需要观众自己做对齐。

页只留图形区之后，素材形状变成宽条（宽高比 1.9~4.3）。A~L 那十二套是给 1080×800 整页排的，宽条塞进"左页右文"会缩成一条看不清的细线——所以按形状再立一族，`S1`~`S12`（名目见 `references/layouts.md`）：上图下文 / 上文下图 / 题签左 / 题签右 / 出血压顶 / 缩图巨字 / 双块并置 / 顶出血压线 / 斜置 / 开窗 / 刻度线 / 巨号垫底。**版面先服从素材形状，再服从句子。**

## 一·补二、无字模式：屏上不写字，文字交给字幕条（2026-11-16 改口径）

`compose_layouts.py --no-head`。默认关（`NO_HEAD = False`），不加这个开关就是一·补那套「屏幕大字 = 口播首分句」。

为什么要有这一档，是量出来的：一镜一刀，屏幕大字只装得下一句 16 字以内；而口播在同一镜里讲 20–37 字、3–5 个信息点。念到第二个点以后画面上没有任何东西在跟，听感就成了「口播已经说到下一页，画面还停在上页」。要么把一镜切成三刀（成本翻倍），要么把文字交给渲染层的字幕条、画面专心做图。

三条实现约定，改的时候别破：

1. **底部留 0.15H 给字幕带**（`SCR = round(H * 0.15)`），图底边贴这条带的上沿（`head_y()`），不是画布垂直居中。居中会让图飘在半空、图与字幕之间空出 200px，观众视线要跳一层。
2. **镜号和装饰线一律挂到图上方**。图贴底之后，图下方就是字幕带，任何东西压进去都会被字幕盖住。
3. **出血上限从 1.04 收到 0.96**（`strip_fit` 的 `max_bleed` 默认值随模式变）。视频页的图形区几乎是贴边的（藏掉了 h1/导语），1.04 加上运镜再推 4–6% 就会切字——实测 01-event 的「1993」「辞去…全部职务」两处都被裁掉。0.96 × 运镜 1.025 ≈ 0.984，仍在画布内。

代价：宽条页受 `max_bleed` 限宽，图高最多到 0.536H（比例 3.45 的页），所以「无字之后把图放大」对宽条页无效。十二套之间的区别只能靠位置、裁切、倾斜、双块、装饰线来撑，不能再靠字的排法。

**已知缺口**：无字分支只写在 `S1`~`S12`，`A`~`L` 这十二套整页版式还没改。一支片里如果 shot plan 同时给了 A~L 和 S 族，会出现一屏有字、一屏没字的混排——要么整片都用 S 族（宽条素材下的默认行为），要么等 A~L 补齐再混用。

## 一·零补九、每镜必须有一个结构件（2026-11-19 定，治「通篇都是文字」）

**骨架阶段最常犯的错不是字丑，是没有图形。** 一集 20 镜全做成「一行大字 + 一条细线」，渲完就是"在用视频念 PPT"。用户原话：「好几个页面都显得太空，通篇都是文字来表述，画面没有结构，没有组件。」四条硬判据，出骨架前逐镜过：

1. **J1 每镜一个结构件**：卡 / 矩阵 / 刻度尺 / 双栏 / 关系图 / 大数字 / 人像 / 引文块 / 流程段，组件里指得出来。**只有大字 + `Rule` 的镜头一律退回重画。**
2. **J2 结构件高度 ≥ 内容区 1/3**：竖版 1080×1920 取 **≥480px**（内容区 y 200–1660），16:9 取 ≥240px。
3. **J3 上下都触到**：内容区下 1/3（竖版 y≥1180）非背景像素不许 < 6%，否则就是"上半截有字、下半截空"。
4. **J4 文字层 ≤2**：标题 + 注，其余信息全进结构件。**大字不算结构件**——≥96px 只满足主角尺寸，不满足"有结构"。

两条配套：

- **句子关系 → 结构件**（按"这句在说什么关系"选，不按"有没有数字"选）：人物卡 / 来源卡 / 引文卡（可先空壳再填满）/ 证据链（编号空格逐个点亮）/ 空格（虚线框 + 问号，明确是"没填"）/ 关系图（节点 + 断开的箭头）/ 双栏 / 汇合（汇到中心圆）/ 分层带（编号 1、2 错位）/ 台账 / 矩阵 / 巨数字 + 对照物 / 流程段。
- **连续镜共用同一套几何**：空壳→填满、单栏→双栏→汇合、分层带立起→逐层展开。坐标写死复用，只改"填了什么"，观众看到的是结构在动，不是换 20 张海报。

完整判据、图元清单（`Panel` / `Meta` / `Glyph` / `Scale` / `BigNum` / `Row`）、下 1/3 留白与主体高度的自检脚本，见 [`references/structure-first.md`](references/structure-first.md)。

## 二、版式由文章推，不由人选

这一步的输入全是 plan 里已经有的东西：

- `claim`（这张图证明哪句话）→ 句子长短、有没有「不是…而是…」、有没有两个数字
- `reads_as`（读者该看见什么）→ 写了「细节 / 局部 / 一角」就该开窗放大
- `figure_type`（这镜是什么形状）→ 是结构、过程、对比，还是给数

**先判 beat（这镜在干什么）**：首镜=起手、末镜=收束；claim 里有「不是/而是/对上/旁边」=对比；结构类图型（unit-grid / kanban / layers / nested / venn / steps / loop / quadrant / tree / pyramid）=拆解；过程类（waterfall / timeline / sankey / journey / gantt）=过程；两个以上数字、或柱/差值/哑铃=给数；其余=叙述。

**再按 beat 取候选**：起手→C/B/A，叙述→A/B/D，过程→D/E/B，对比→I/J/B，拆解→G/H/E/J，给数→A/H/I/B，收束→L/I/K。两个修正：`reads_as` 有细节词 → 开窗 H 提前；句子 >18 字 → 剔竖排单列，≤12 字 → 剔双列并优先 C。

**最后过全局约束**（这些是 FAIL，不是「看着顺眼」）：

| 约束 | 为什么 |
|---|---|
| 相邻两镜不同版 | 连着两镜一个手法，第三镜观众就走了 |
| 首镜不许切页/开窗/出血/压边 | 开场得先把整页立住，否则第一秒看不懂这是什么 |
| 末镜压边（撞了改出血） | 收束要「翻过去」的手感 |
| 长句不许进竖排单列；短句用双列只算 WARN | 竖排吃字，一句 22 字会顶出画面 |
| 全片至少一套竖排、一套重手法 | 横排铺到底，画面没有呼吸 |
| 8 镜以上要有一次巨号编号 | 中段给观众一次节奏点 |
| ≤12 镜时一套版只用一次 | 库里有 12 套，够轮；重复是懒 |
| 每镜必须写 `why` | 说不出它服务哪句话，就别用这套 |

### 一页两拍（`frames`）

一页一镜是底线。信息密的页给两拍：**第一拍全景，第二拍推近**（`compose_layouts.py` 按画面重心裁 1/1.26 再放回原尺寸，音频仍是同一段、时长对半分，不用重配）。

什么时候拆，也由 plan 里的话决定：

- `reads_as` 写了「细节 / 局部 / 一角」且是拆解类 → 这页有个点值得再看一眼；
- 拆解类 claim 超过 18 字、过程类超过 22 字 → 一页要装两层意思，一拍讲不完。

首镜、末镜永不拆（开场要一次立住整页，收束要一次到位）；10 镜最多 2 处拆拍——全是推近，就不叫推近了。这两条都是 FAIL，不是建议。

同一篇文章，机器排出来的顺序和人手排的会不一样，这是好事——**这一步的价值就是不用人再做一遍审美决策**。

## 三、十二套版面（`compose_layouts.py`）

画的不是「文字放哪」，是**页与字的图文关系**：字压页、页遮字、页开窗、竖线分栏、巨号垫底、字出血。全表与踩坑见 `references/layouts.md`。

| 版 | 手法 | 一句话 |
|---|---|---|
| A / B | 页左·字右横排 / 页右·字左横排 | 最稳，底色用 |
| C / D | 页左·竖排单列 / 页右·竖排单列 | 批注口吻，短句 |
| E | 页左·竖排双列 | 长句也能竖 |
| F | 批注式：页铺满，小字竖排在页外 | 页自己就是主角 |
| G | 字块切页：字压页右侧留白，纸色底衬只压 58px | 图文咬合 |
| H | 开窗放大：右下开一块「局部放大」，裁右下 52%×48% | 用放大代替重讲 |
| I | 字出血：92px 巨字贴边 | 全片结论句 |
| J | 竖线分栏：一条线切开，字在左竖排 | 转折 |
| K | 巨号编号垫底（190px `06`） | 只调节奏 |
| L | 出血压边：页右侧出画 62px | 收尾 |

编排器 `PREFER` 按字数分 band 选版并避开最近两镜；也可以像样例那样在 `--headlines` 里显式给 `layout`，显式优先。

## 四、屏幕大字谁写

**由 AI 从 `claim` 重写，不是手写项。** `scripts/conclusions.py` 只是没人盯时的机械兜底：砍时间前缀 → 在标点边界取最长窗口 → 砍两三个字的悬空拖尾（`--max 26`）。机器压出来的句子会断半句（「执掌 33 年的 CEO 把总裁」），所以有 AI 在场时必须自己重写。

## 五、硬规矩（构图、诚实）

**构图**

- 页与字**不许互相遮挡正文**：纸色底衬只压页面右侧留白那 58px；出血压边只在 62px 以内；开窗裁的是页面局部，不许把整页缩小再放一遍（那是「复制两遍」，不是放大）。
- 页面缩放全片用**同一个系数**，否则每镜字大小跳动，像不同的片子拼起来。
- 大字基线至少距画面边 40px；竖排字列间距 ≥ 相邻两列字宽。
- 一镜只说一句话。一句讲不完就先拆镜，不是缩字号。

**诚实**

- 屏幕大字必须能落回 `claim`；`claim` 又必须能落回原文（`article-figures` 的 `plan_check.py` 已经查过 `anchor_quote`）。
- 数字、金额、时长不得在构图层新增；构图层只搬字，不造事实。

## 七、依赖与已知限制

- **Python**：`pillow` 足够，不需要浏览器。
- **字体**：屏幕大字用汇文明朝体（`.otf`）。不写死路径：`ARTICLE_VIDEO_FONT` 指文件，或 `FIGKIT_FONTS` 指字体根目录（与 `article-figures` 共用）。找不到会明确报错，不会静默换字。
- **渲染**：两个抽屉并存。`step4-motion`（Remotion，元素级动画，现在走这条）；`video/make.mjs`（HyperFrames + 本地 VoxCPM，留作旧路径）。没配音时复用已有 `narration.wav` / `alignment.json`。
- **`@remotion/captions`**：分句字幕用它的 `createTikTokStyleCaptions()`（见「一·零补五」）。`step4-motion/node_modules` 里已带 4.0.544，但 `package.json` 没声明——重装依赖前先确认，缺了这个包字幕会编译失败。
- **已知限制（都在代码里留了印记，不是"以后再说"）**：
  - 推近帧按**整帧裁**，不是按某个元素推；图上要精确推某根柱，得在 shot plan 里手写 `focus:{x,y}`（字段还没实现）。
  - `build_script.py` 要求帧数与配音镜数一致：改镜数就得重配音，这是引擎侧的约束。
  - 竖版（1080×1920）要改 `compose_layouts.py` 头部的 `W/H` 常量，还没做成 `--size` 参数。
  - `K` 的巨号按镜次奇偶换角（左上 / 右下），只支持这两个角。
  - **`make.mjs` 会误判没有 VoxCPM**：本机首次加载 VoxCPM 实测 233s，而探测窗口 60s，`make.mjs` 直接报"没有可用的配音方式（要求 voxcpm）"。绕法：先单独跑
    `node video/step2-voice/voice.mjs <script.json> --backend voxcpm --voice news-man`，成功后再 `make.mjs --skip-voice` 复用 `narration.wav` / `alignment.json`。
  - **字幕条是二选一的口径**：默认不带逐字字幕条——屏幕大字自己就是那一句（口播的首个分句），再加一条字幕会和它重复；走 `--no-head` 时反过来，屏上不写字、字幕条由渲染层画。两种不能混着用，理由与代价见「一·补二」。
  - **`--no-head` 只覆盖 `S1`~`S12`**，`A`~`L` 仍是带字版；混排会一屏有字一屏没字。
